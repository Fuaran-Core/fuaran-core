# Migration: typed, attested provenance (`0.0.1-alpha.13`, Phase 320)

**What changed.** The op-stream actor went from a bare `string` to a typed `Actor` DU
(`Human of id | Agent of model * version * id`) that is **folded into the chain hash**. Before
alpha.13 the actor was recorded but the canonical payload encoded it as a bare JSON *string*; the
typed actor encodes as a JSON *object*, so the canonical hash pre-image changed — **a one-shot
breaking hash-format bump.** Attribution is now part of the integrity chain: re-attributing an op
breaks `verifyChain` (linear) / `verifyDag` (DAG) exactly as tampering with the op does.

Two further additions ride along:

- an optional **`IAttestationSink`** that signs chain checkpoints (the head at a commit / publish
  boundary — O(commits), not O(ops); the hash-chain attests the whole prefix). Default `noAttestation`
  is a no-op, so signing is opt-in.
- **replay-as-provenance** is documented + tested: a state is provably the deterministic replay of
  its (attested) op log / op-DAG, and a signed head + replay is independently re-verifiable.

**Why now.** Folding the actor into the hash is a one-shot breaking change. Cheap before any
op-stream is persisted, painful after — the existing Phase-255 `rehash` / `StreamConfig` migration
seam absorbs it, so doing it now costs a config-aware re-hash of history, not a flag day.

## Surface

```fsharp
// new — the typed actor
type Actor =
    | Human of id: string
    | Agent of model: string * version: string * id: string

module Actor =
    val encode        : Actor -> string      // canonical JSON object (the hash pre-image)
    val id            : Actor -> string       // the stable attribution id of either case
    val ofLegacyString: string -> Actor       // lift a pre-320 bare-string actor to `Human`

// changed signatures (actor : string  ->  actor : Actor)
type OpRecord<'Op>    = { Seq: int; Actor: Actor; Op: 'Op; PrevHash: string; Hash: string }
type StreamConfig     = { Payload: int -> Actor -> string -> string; Genesis: string }
val OpStream.append      : HashFn -> StreamWitness<_,_,_> -> Actor -> 'Op -> 'State -> OpRecord<'Op> list -> Result<'State * OpRecord<'Op> list, 'Rej>
val OpStream.appendWith  : StreamConfig -> HashFn -> StreamWitness<_,_,_> -> Actor -> 'Op -> 'State -> OpRecord<'Op> list -> Result<'State * OpRecord<'Op> list, 'Rej>
val Dag.append           : HashFn -> StreamWitness<_,_,_> -> Actor -> 'Op -> string -> Dag.T<'Op> -> string * Dag.T<'Op>
val Dag.merge            : HashFn -> StreamWitness<_,_,_> -> Actor -> 'Op -> string -> string -> Dag.T<'Op> -> string * Dag.T<'Op>
type DagNode<'Op>     = { Id: string; Parents: string list; Actor: Actor; Op: 'Op }

// migration helpers
val OpStream.legacyActorConfig   : StreamConfig                                       // the pre-320 bare-string payload
val OpStream.fromJsonlLegacyActor: StreamWitness<_,_,_> -> string -> Result<OpRecord<'Op> list, string>

// attestation seam (default no-op)
type Attestation      = { Head: string; KeyId: string; Signature: string }
type IAttestationSink =
    abstract member Sign  : head: string -> Attestation option
    abstract member Verify: attestation: Attestation -> head: string -> bool
val OpStream.noAttestation    : IAttestationSink
val OpStream.head             : OpRecord<'Op> list -> string
val OpStream.attestHead       : IAttestationSink -> OpRecord<'Op> list -> Attestation option
val OpStream.verifyAttestation: IAttestationSink -> Attestation -> OpRecord<'Op> list -> bool
```

## Migration recipe (a host with persisted pre-320 streams)

A linear stream persisted before alpha.13 has bare-string actors and hashes computed under the old
payload. Migrate it with the standard Phase-255 shape, using the supplied legacy config:

```fsharp
// 1. read the pre-320 file — bare-string actors are lifted to `Human`
match OpStream.fromJsonlLegacyActor sw oldJsonl with
| Error e  -> // structurally malformed — investigate
| Ok recs ->
    // 2. confirm it is intact under the old bare-string payload
    if not (OpStream.verifyChainWith OpStream.legacyActorConfig OpStream.defaultHash sw recs) then
        // the file does not verify under the legacy format — do not migrate
    else
        // 3. re-hash to the new typed-actor canonical format
        match OpStream.rehash OpStream.legacyActorConfig OpStream.canonicalConfig OpStream.defaultHash sw recs with
        | Ok migrated -> // migrated |> verifyChain defaultHash sw  ==>  true; persist it
        | Error e     -> // legacy chain did not verify — investigate
```

The ops / seqs / actors are the source of truth; only the hash chain changes. After migration, drop
the legacy config and use the plain `append` / `verifyChain`. A host that never persisted a stream
skips all of this — `canonicalConfig` is the default and every in-memory `append` already produces
the typed-actor chain.

**Promoting a `Human` to an `Agent`.** `ofLegacyString` always lifts to `Human` (a pre-320 bare
string carried no model/version). A host that knows a legacy actor was actually an AI agent
re-maps the records' `Actor` field before step 3 (`rehash` re-derives the chain from whatever the
records now carry), so the agent's `model` / `version` enter the hash at migration time.

**The op-DAG.** `Dag` node ids *are* content hashes that now fold the typed actor, so a pre-320
persisted DAG cannot be re-hashed in place (its ids change). The DAG migration is a rebuild: read
the legacy nodes, re-append them in topological order under the new hash. Linear streams are the
common persistence path and migrate via `rehash` above; pre-320 persisted Core DAGs are not expected
in practice (the DAG is the opt-in, rung-4 surface).

## Cross-host coordination (REQUIRED — this is a wire-format break)

The hash pre-image is a cross-host contract. Every conformant host MUST adopt the typed-actor object
+ the same field ordering (`kind` first; `Human`→`{kind,id}`, `Agent`→`{kind,model,version,id}`) in
the same release, or their chains diverge:

- **F# host (`Fuaran.Core.*`)** — shipped here (alpha.13).
- **TypeScript host** — must bump its op-stream codec + hash pre-image to the typed-actor object.
- **Python host** — same.
- **Fuaran.UI op-record host** (`Fuaran.UI.OpStream.Abstractions` `HashChain.computeHash` +
  `OpRecord.UserId` → typed actor) — a UI-tier adoption that folds the actor into the UI SHA-256 hash
  and renames the wire field; **deferred and to be coordinated with the wire-versioning work
  (Phase 319)** so the op-stream wire shape takes a single coordinated break rather than two. The UI
  `wire-format-fixtures/` corpus regenerates as part of that adoption.

## Replay-as-provenance

The contract a verifier checks, given only the records (or DAG) + an attestation:

1. **Integrity** — `verifyChain` (linear) / `verifyDag` (DAG) recomputes every hash, proving the log
   was not reordered, dropped, op-tampered, **or re-attributed** (the new property).
2. **Attestation** — `verifyAttestation` (linear) / the sink's `Verify` (DAG head id) re-checks the
   host signature over the head. The hash-chain attests the whole prefix, so one head signature
   covers every prior op.
3. **Determinism** — `replay` / `Dag.replayTo` re-derives the state by folding the witness reducer
   over the log; it is deterministic (the DAG topo order is total), so the state is *provably* the
   product of exactly this attested op set.

Tampering with any op or actor breaks step 1, so the attested head is no longer the legitimate
product of the log — provenance is independently falsifiable, not merely asserted.

## Verification

`Fuaran.Core.Tests.ProvenanceTests`: the op-record carries a typed Human/Agent actor; re-attributing
an op breaks `verifyChain` and localises to the record with an `actor` break reason; the typed actor
round-trips through JSONL; a pre-320 legacy stream verifies under `legacyActorConfig` and not under
canonical; `fromJsonlLegacyActor` + `rehash` migrates a pre-320 file into the typed-actor format with
actors preserved and replay-state unchanged; the no-op sink signs nothing; a sink signs the head and
the signature re-verifies; linear + DAG replay-as-provenance is independently re-verifiable and
falsified by re-attribution.

## Rollback

Not additive — this is a breaking hash-format change. To roll back, a host reverts to alpha.12 and
re-hashes any alpha.13 stream back to the bare-string payload (`rehash canonicalConfig
legacyActorConfig`), accepting the loss of the Human/Agent distinction (all actors collapse to their
id). The attestation surface is purely additive — ignoring `IAttestationSink` leaves behaviour
unchanged.
