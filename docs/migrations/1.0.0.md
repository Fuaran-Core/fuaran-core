# Migrating to `1.0.0` (Phase 386)

`1.0.0` removes what the `0.x` line marked as leaving and closes three shapes a consumer could
build around. Nothing on the wire moves except the retired `RowCodec` document and one reader
spelling of a value space (the last row, Phase 405). Written for a consumer pinned anywhere from
`0.20.0`: every spelling below existed at `0.20.0` or arrived later as a forward, and each row is
the one-line edit. The full record is
[`docs/releases/1.0.0.md`](../releases/1.0.0.md).

| What left | Write instead |

| a STORED value space in the descriptor spelling — `{"kind":"stringLen","minLength":1,"maxLength":4}`, the shape `SpaceCodec.descriptorJson` and `Function.toSchema` write — handed to `SpaceCodec.decoder` or inside a capability, refusal or pipeline document | re-write it in the document spelling, `{"$type":"stringLen","min":1,"max":4}`: `"kind"` becomes `"$type"`, and a string length's `minLength` / `maxLength` become `min` / `max` (every other member is spelled the same). Read with a `0.36.0` reader and re-encode with `SpaceCodec.toJson` to convert in bulk. Why: a value space has ONE reader spelling across 1.x, and `1.0.0` refuses the other as a missing `"$type"` rather than freezing two (DECISIONS.md D135). `toSchema`'s output is unchanged: it is a descriptor, never read back |

**Verify.** Build against `1.0.0` with `TreatWarningsAsErrors` off: every row above but the last
is a compile error, never a behaviour change. The last is a refusal at read time, `MissingField`
at the value space's `$type`, so search stored documents for a value space carrying `"kind"` and
no `"$type"` before you upgrade. A host that runs the conformance kit sees the `…At` ids in its
census and the observer family's two laws (the adapter laws left with the adapter).

**Roll back.** Pin `0.36.0`; every row above still compiles there (the `…At` spellings too), and
its reader takes both spellings of a value space, so a re-written document reads there unchanged.
