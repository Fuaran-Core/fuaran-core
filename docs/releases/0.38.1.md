## 0.38.1 — DRAFT

**Moved number (2026-10-16).** `0.38.0` was packed as a draft with earlier public surfaces of `Fuaran.Core.Wire` and `Fuaran.Core.OpStream` than the release commit's, and a released version names one contract, so the slot advances to `0.38.1` and `0.38.0` is never released. Every entry below that says it rides the `0.38.0` slot or draft ships in `0.38.1`; nothing else changes.

The minor after the released `0.37.0`. It opens over `v0.37.0` and carries the proof-gap work of the
2026-10-12 objective: additive here unless an entry says otherwise. Through the `0.x` line a breaking
class rides a minor ([`STABILITY.md`](../../STABILITY.md), "Versioning policy").

### Breaking

- **`Decoder.fail` takes a `RootDecodeCode`** (Phase 443, `Fuaran.Core.Wire`) — a new closed union of the
  seven codes a refusal at the value can carry: every `DecodeCode` but `MissingField` and `InvalidJson`,
  which at the empty path mint a refusal that does not resolve (a `MissingField` names no member; an
  `InvalidJson` stops resolving one member down). The old call no longer compiles, and the model's
  `fail_sound` now holds for every code `fail` accepts; the claims-ladder row
  `decode-layer-refuted-premises` names only `andThen` (DECISIONS.md D149). `DecodeCode` is unchanged and
  is still what a refusal carries; nothing on the wire moves. **Migration:** pick the `RootDecodeCode`
  case of the code you passed (`Decoder.fail DecodeCode.SchemaFault` becomes
  `Decoder.fail RootDecodeCode.SchemaFault`), or raise an absent member's `MissingField` through
  `Decoder.field`.
- **`Tree.Index.isFreshFor` is exact, and takes a content encoder** (Phase 447, `Fuaran.Core.Tree`) — one
  walk compares the index with the tree node by node, with no hash: the root id, no id carried twice,
  every node's kind, ordered child ids and `encode` reading against the cached node, every child's
  parent link, and no key in either map beyond the tree's. The retired 32-bit `Fingerprint` stamp could
  read a changed tree as fresh (Phase 438 pinned a collision), and the check was blind to a
  content-only `UpdateNode`. Behavioural: an index the old check called fresh may now read as stale —
  after a stamp collision, after a content-only edit, and over any tree carrying an id twice (`build`'s
  own included). Surface: `isFreshFor w idw encode root ix` gains `encode`; `NodeIndex.Fingerprint`,
  `Index.buildWith` and `Index.isFreshForWith` are removed (with the stamp gone, `buildWith` was `build`
  and `isFreshForWith` was `isFreshFor`); `Ops.Index.afterOp`'s signature is unchanged and its index is fresh under any
  encoder. Proved with no hash premise (`freshness_tracks_change`); the claims-ladder row
  `index-stamp-separates` is retired and `index-node-is-its-record` restated (DECISIONS.md D150).
  **Migration:** `Index.isFreshFor w idw root ix` becomes `Index.isFreshFor w idw encode root ix` with the
  node encoder you hash content with (`fun _ -> ""` asks for the structural check alone);
  `Index.buildWith w idw encode root` becomes `Index.build w idw root`; `Index.isFreshForWith` becomes
  `Index.isFreshFor`; drop any read of `NodeIndex.Fingerprint`. **Consumers:** a survey on 2026-10-12
  found no caller of `isFreshFor`, `buildWith`, `isFreshForWith` or `NodeIndex.Fingerprint` outside Core,
  so no consumer migrates.
- **`Decoder.andThen`'s function refuses with a `RootDecodeCode`** (Phase 453, `Fuaran.Core.Wire`) — it
  answers `Result<'U, RootDecodeCode * string * string>`, the triple `Decoder.fail` takes, and `andThen`
  raises that refusal at the value, as `fail` does. It answered a whole `DecodeError` and was passed
  through untouched, so a function refusing with a path of its own, or with `MissingField` /
  `InvalidJson`, minted a refusal that need not resolve. The old call no longer compiles; the model's
  `and_then_sound` now holds for every function, the claims-ladder row `decode-layer-refuted-premises` is
  retired, and `decode-layer-refusal-premises` keeps only the `Codec.make` / `ofDecoder` reader
  (DECISIONS.md D151). No refusal any Core decoder answers changes, and nothing on the wire moves.
  **Migration:** `Error(DecodeError.make DecodeCode.X expected message)` becomes
  `Error(RootDecodeCode.X, expected, message)`; a function that refused at a path of its own becomes
  `Decoder.bind` to `Decoder.at <path> (Decoder.fail ...)`, which walks the path in the document.
  **Consumers:** a survey on 2026-10-14 found every `Decoder.andThen` caller inside Core, all migrated
  here, so no consumer migrates.

- **`QueryCodec.decodeDeferredResultDetailedWith` refuses with the fault's own code and path** (Phase
  455, `Fuaran.Core.Query`) — the typed async-result reader read through the string envelope reader and
  answered every refusal `OutOfRange` at the root; it now reads through the envelope's typed reader
  (`CapabilityCodec.deferredDecoder`, internal), so a missing `$type` is `MissingField` at `$type` and a
  page's `pageNum` that is not an integer is `WrongKind` at `value.pageNum`. The wire is unchanged and
  every document that decoded still decodes to the same value; `decodeDeferredResult`'s sentence names
  the fault for the same reason (DECISIONS.md D153). **Migration:** a caller matching the old
  `OutOfRange` at `[]` matches the refusal's own code. **Consumers:** none found outside Core reading
  the refusal's code.

- **`Propagation.dirtyFromOp` is seeded from the diff of the two trees** (Phase 456,
  `Fuaran.Core.Propagation`) — it closed over `touchedBy` alone, and so left clean a node the op
  touches no container of but whose declared reads the edit moved (a node reading every leaf below it,
  a leaf inserted two levels down). It now closes over the seeds `changedForOp` has used since Phase
  308, computing the post-edit tree with `Ops.apply` (an op `Ops.apply` refuses closes over `touchedBy`
  as before), and `changedForOp` is its restriction to the survivors. The set only grows: every member
  it named it still names. Proved complete and least over its seeds (`dirty_from_op_complete`,
  `dirty_from_op_least`), and the composition with `evalFrom` is a theorem for an evaluator that is a
  function of a node's kind, child ids and declared reads (`evalfrom_agrees_for_op`); DECISIONS.md
  D154. **Migration:** none for a caller treating the set as what to recompute; a caller pinning the
  exact set re-pins. **Consumers:** none found outside Core.

- **The JSON reader refuses a repeated member name and a raw control inside a string, at every decode
  entry point** (Phase 462, `Fuaran.Core.Wire`; `Fuaran.Core.Idl.Codegen`'s TypeScript reader) — Core owns the
  JSON-syntax layer every Fuaran wire cites (`docs/conformance-corpus.md`, "The JSON-syntax layer"; DECISIONS.md
  D157). `JsonErrorKind` gains `DuplicateMember` (`union-widening`: an exhaustive match over the kind gains an
  arm), raised at the repeated name's opening quote when the member is accumulated; a raw U+0000 to U+001F
  inside a string is `BadEscape` at the character. Behavioural: a document some entry point accepted — a
  repeated key (read first-wins since Phase 347, D113, now superseded), a raw control — is refused by `parse*`,
  `parseDetailed*`, the tolerant reads, `Decode.parse*`, `Decoder.parse*` and `Json.Reader.read` alike, and by
  the generated TypeScript reader. Under `EraseMemberNull` an erased member null is not an occurrence of its
  name. `Json.firstRepeatedMember` is new, and both guarded renderers (`Json.tryRender`, `Canon.tryRender`)
  refuse a value whose object repeats a name, third after the non-finite float and the ill-formed string; the
  total renderers are unchanged. The `refusals/` family gains 34 vectors and the `decode/` family 6; the parser
  and canon models carry the rows (`DuplicateMember`, `CCtrl`, `distinct_keys`). **Migration:** an exhaustive
  match over `JsonErrorKind` adds the `DuplicateMember` arm; a caller relying on first-wins over text (none
  found outside Core) repairs the document or reads through `repair` on its own side. **Consumers:** every
  cohort member re-pins at the cut; the op-stream JSONL scanner's own answers are Phase 466's.

- **The op-stream JSONL reader refuses a repeated key, a raw control and a raw unpaired surrogate, at every
  depth, by path** (Phase 466, `Fuaran.Core.OpStream`; DECISIONS.md D158) — the line scanner every op-stream
  reader shares (`fromJsonl*`, `Snapshots.ofJsonl`, `captureFromJsonl`, `Attributed.decodeEnvelope`,
  `Dag.fromJsonl`, and `checkRaw` under the checked writers) reads by the strict grammar `Wire.Json` reads by
  (D157), sharing its vectors and not its code (D2). `JsonlFaultReason` gains `ExpectedCommaOrBracket`,
  `RepeatedKey path`, `RawControl path` and `LoneSurrogate path` (`union-widening`: an exhaustive match gains
  four arms), each path spelled as `DecodePath.render` spells one. Behavioural: a line holding a repeated key
  (read first-wins since Phase 45), a raw U+0000 to U+001F in a string, or a raw surrogate that is not half of
  a pair is refused; an array or object value is read by its grammar at every depth rather than balanced, so a
  malformed value its decoder used to refuse is refused at the line; a surrogate pair split between a raw unit
  and an escape now reads, as `Wire.Json` reads it. An unpaired surrogate escape keeps `InvalidEscape`. Every
  committed store in the workspace was scanned under the new rules first (D158.1). The model
  (`proofs/OpStreamLoad.fst`) moved first and its three theorems are re-proved. **Migration:** an exhaustive
  match over `JsonlFaultReason` adds the four arms; a store holding such a line repairs it before its readers
  take the version. **Consumers:** every cohort member re-pins at the cut.

- **Every checked op-stream writer refuses a string it quotes that the strict reader would refuse** (Phase 473,
  `Fuaran.Core.OpStream`, `Fuaran.Core.OpStream.Dag`; DECISIONS.md D160, closing D158.6) — `tryToJsonl`,
  `tryCaptureToJsonl`, `Snapshots.tryToJsonl` and `Dag.tryToJsonl` hold every member a line carries to
  `Jsonl.checkRaw`, in line order: the span they embed, as before, and now the strings they quote themselves (a
  record's `actor`, `prevHash`, `hash`; a capture's `eff`, `det`, `prevHash`, `hash`; a snapshot's `prevHash`,
  `hash`; a node's `id`, `parents`, `actor`). Behavioural: a value carrying an unpaired surrogate in one of them,
  which the writer returned `Ok` and the Phase-466 reader refused, is refused at the write as
  `Unreadable(LoneSurrogate path)` by member. No public signature moves. **Migration:** none for a writer of
  well-formed strings; a caller writing an unpaired surrogate repairs the string before it appends.
  **Consumers:** every cohort member re-pins at the cut.

### Additive

- **`Json.parseWithLimits` — the parser takes a limits record, enforced on the way down** (Phase 465,
  `Fuaran.Core.Wire`, DECISIONS.md D159) — a wire host bounds the parse through Core alone, with its own
  specification's values. New: `JsonLimits` (`MaxDepth`, `MaxStringLength` in Unicode code points,
  `MaxArrayLength`, `MaxObjectMembers`, `MaxDocumentBytes` in UTF-8 bytes) with `JsonLimits.depthOnly`;
  `JsonLimit` (the five bounds, with `JsonLimit.name` — the wire names `depth` / `stringLength` /
  `arrayLength` / `objectMembers` / `documentBytes` — and `JsonLimit.declared`); `JsonLimitBreach` (the
  limit, its declared value, the path to the container the breach was raised in, the position — never the
  input); `JsonRefusal` (`Malformed of JsonError` | `LimitExceeded of JsonLimitBreach`);
  `Json.parseWithLimits policy limits input : Result<JVal, JsonRefusal>`; `DecodeError.ofJsonRefusal` (a
  breach is `LimitExceeded` at its path, never `InvalidJson`); `Decoder.parseWithLimits limits json`.
  Every pre-existing entry point (`parse`, `parseDetailed*`, the tolerant reads, `Decoder.parse*`,
  `Json.Reader.read`) is unchanged in behaviour — the 512-deep stack guard and no size limit — and
  `JsonErrorKind` gains no case. `PathSegment` is declared in `Json.fs` rather than `DecodePath.fs`; its
  full name is unchanged. **Stability:** `JsonLimits` is a public record a host constructs in full — a
  field added later is `record-widening`, breaking, and is advanced as one. Proved first in
  `proofs/JsonParse.fst` section 13 (`limited_at_no_bound_is_the_parser`,
  `limit_never_reported_as_malformed`, `bytes_checked_before_the_descent`, `string_bound_exact`,
  `items_bound_exact`, `limits_exhibited`); the `decode/` family gains seventeen limits vectors, each
  declaring its `limits` record.

- **`Conformance.streamLaws` declares the ladder row it discharges** (Phase 454) — its entry in
  `Families.obligations` now names `op-stream-load-premises`, the `domain-obligation` row the op-stream
  load model's round trip stands on (the witness's `Decode` inverts its `Encode`, the records it chains
  are well formed), which the family's JSONL cell already sampled at a domain's own witness. No
  signature changes; the discharge relation the kit reports gains one pair.

- **`Conformance.codecLaws codec gen seed iterations`** (Phase 442) — a new opt-in law family
  (`seam-not-every-domain-has`, guarded on the mutation outcome and on distinct written values, refusal
  population drawn) that samples, at a domain's own `Codec<'T>`, the premises Phase 436 proved the codec
  building blocks under: every drawn value is written, every written value reads with no defect and reads
  back equal, the canonical text under every encoding profile reads back as the value, and every refusal of
  a structurally mutated written document resolves in it with a sound code (not `InvalidJson`). It
  discharges the claims-ladder rows `decode-layer-round-trip-premises` and `decode-layer-refusal-premises`,
  now `domain-obligation` (DECISIONS.md D148). One new public function on the `Conformance` facade; no
  existing signature changes. The roster grows from 98 to 99 families.

- **A collecting decoder binds each type parameter's short-circuiting decoder under its documented name**
  (Phase 460, `Fuaran.Core.Idl.Codegen`) — under `Gen.Derivation.SpecDecoders`, the collecting `col*`
  decoder of a parameterised union now binds `dec<V>` (the short-circuiting decoder's own name for its
  type-parameter decoder, `JVal -> Result<'V, DecodeError>`, here `cFirst` over `col<V>`), so a `TFn`
  placeholder that names it compiles in BOTH emitters. Until this a vocabulary whose placeholder called
  `decT` generated a module that did not compile once it opted into the collecting decoders (FS0039).
  What a placeholder may reference is now stated as contract at the F# decoder emitter's `TFn` arm: the
  module's prelude and generated `dec*` decoders, and inside a parameterised union each `dec<V>`; every
  other local (`col<V>`, `__j`, `__fs`, `j`, member bindings) is an emitter internal. Generated output
  moves only for a parameterised union under `SpecDecoders` (one `let` per type parameter); a refined
  case's short-circuiting twin takes the same bindings. No public signature changes.
