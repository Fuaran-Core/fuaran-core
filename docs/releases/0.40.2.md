## 0.40.2 — DRAFT

**Slot class: additive.** The patch after the released `0.40.1`. It opens over `v0.40.1`, which is a
consumer's contract, so nothing rides it; the work in this slot is additive, which makes it a PATCH slot, and
a member of a higher class advances it to the `0.41.0` minor rather than riding it ([`STABILITY.md`](../../STABILITY.md),
"Versioning policy"). Phase 467 opens it.

### Additive

- **`Reader` has a token surface, so a wire host with position-dependent null rules reads through Core's
  reader alone** (Phase 467, `Fuaran.Core.Wire`; DECISIONS.md D213) — class additive. `JsonToken` (`Null`,
  `Bool`, `Number`, `String`, `Array`, `Object`) is the kind of the value due; `Reader.peek` answers it without
  reading, `Reader.path` says where the value stands, and `Reader.readNull` reads a `null` token on the host's
  own rule, consulting no policy. The readings that build `JVal` (`value`, the typed arrays), both `NullPolicy`
  cases, the erasure `members` performs under `EraseMemberNull`, and every refusal code, path and sentence are
  unmoved; the re-scan `Reader.read` runs after a shape mismatch admits the nulls the reading read on its rule,
  and answers a null the reading never reached by the read's policy, as before. The canonical reading over the
  tokens is proved to be the strict parse on every input (`proofs/JsonParse.fst` section 14,
  `reader_rebuilds_the_parse`; ladder row `reader-rebuilds-the-parse`), and the extracted model is held to it
  beside production. A case added to `JsonToken` would be breaking: it is a closed union a host matches
  exhaustively.

### Internal

- **The oracle manifest is one line per binary** (Phase 555, `.github/workflows/publish-packages.yml`) — no package,
  wire or proof byte moves. `v0.40.1` was the first tag to publish the oracle binaries, and its `oracle-build` job
  collected `publish-oracle.ps1`'s build output into the manifest lines, so `fuaran-core-oracle-0.40.1.sha256`
  carries 36 lines: the four correct `sha256  name` lines among the build log. The binaries are the ones the manifest's
  sha lines name. `oracle-release` refused the attached manifest after attaching it, so `v0.40.1`'s publish run is red
  on that job. The build output now goes to the log, and `oracle-build` refuses a manifest that is not exactly four
  well-formed lines, before anything is attached. This changes `publish-packages.yml`, so the publish-gate exercise in
  `RELEASING.md` runs again before this slot is tagged.
