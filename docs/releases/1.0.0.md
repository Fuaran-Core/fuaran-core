## 1.0.0 — DRAFT

The first major. It opens over the released `0.36.0` and is the one slot where a removal is free:
the `0.x` line's scheduled removals land here, and from this slot the version is semver
([`STABILITY.md`](../../STABILITY.md), "Versioning policy"). A consumer's edits, from any `0.x`
pin back to `0.20.0`, are [the 1.0.0 migration](../migrations/1.0.0.md).

### A kind projection carries its message map and declares its record's fields (Phase 403) — BREAKING-SOURCE: `Gen.KindProjection` gains `MapMsg` and `RecordFields` (`record-widening`); the support document gains two optional keys (`additive`); an emission over a projected kind that cannot read its record now refuses

**The class, from the gate.** The surface family prints `Fuaran.Core.Idl.Codegen` **`record-widening`**:
`Gen.KindProjection` gains the record fields `MapMsg: string option` and
`RecordFields: IdlField list option`, so its constructor is a `retype` and every full-literal
construction of a projection stops compiling (`FS0764`) until it names both. The wire family prints
the `supportArtifact` baseline **`additive`**: a projection may now carry `mapMsg` and
`recordFields`, and a projection declaring neither renders byte for byte as it did, so every
existing `support.json` reads unchanged under encoding version 1. No other baseline, wire byte or
committed generated module moves.

**Why.** A kind projection (`Gen.KindProjection`) replaces a kind's record, encoder and decoder with
host source. The generator then has no way to know the record's shape, yet three emissions read it:

- `Derivation.MapMsg` refused a vocabulary with a projected kind ("the message map over the
  projected kind …"), and a projection had no member through which a host could supply the one
  piece the generator cannot construct. A host with a projected kind kept a hand-written message
  map beside its otherwise generated layer — the walk a new kind can be missed by.
- `Derivation.SlotsOf`, the node witness (`children` / `withChildren`, private or under
  `StructuralAccess`) and `KeyedPositions` read the kind's WIRE fields as if they were the
  record's. Where the two differ — a wire key optional where the record's member is required, two
  wire keys merged into one member — the emission did not compile: a host's `SlotsOf "Binding"`
  produced `match s.On with Some …` against a required `On` (`FS0001`). A generator that emits
  source that does not compile is a defect, not a limitation.

The design, the refusal rules and the rejected alternatives are DECISIONS.md D132.

**What moved, for a consumer.**

- **`KindProjection.MapMsg`** — the full `and private mapMsg<Tag>Spec<'Msg, 'Msg2> (f: 'Msg -> 'Msg2)
  (v: <Tag>Spec<'Msg>) : <Tag>Spec<'Msg2> = …` member, verbatim, written once in host source beside
  the record as `Mk` already is. `Derivation.MapMsg` joins it to the derived message map's
  recursion group, so it may call `mapMsg f` and every derived `mapMsg<Decl> f`. With `None`, the
  refusal stands with the same construct, principle and alternative: the generator does not guess a
  map.
- **`KindProjection.RecordFields`** — the projected record's fields at their HOST shapes (name as a
  wire field is spelled, the member being its PascalCase; type; optionality). The witness, the keyed
  walk and the slot enumerators read these in place of the kind's wire fields. A declared field at a
  type the module does not declare is refused by name ("the projected record field 'Gate.owner' at
  the undeclared type 'Owner'").
- **With `RecordFields = None`, an emission that would read the record refuses by name** instead of
  emitting source that may not compile: the node witness and `StructuralAccess` when the kind's wire
  holds a node directly ("the node witness's children of the projected kind …"), `KeyedPositions`
  when it holds one anywhere ("the keyed node positions of the projected kind …"), and `SlotsOf`
  always ("a slot enumerator over 'T' through the projected kind …"), because a record may hold a
  value of the type that its wire spells otherwise. A projected kind whose wire holds no node still
  emits a plain module with no declaration: a node on no wire key is a node no host reads back, so
  the record holds none.
- **`support.json`** carries the two members as `mapMsg` and `recordFields` on a projection entry,
  the fields in `idl.json`'s own field shape (one codec for both documents), and `Diff` compares
  both as part of the projection's support entry.

**Adopting it.** Name both members in every full-literal `KindProjection` (`MapMsg = None;
RecordFields = None` keeps today's emission wherever no refusal above applies). A host whose
projected kind's wire holds a node — `Switch` in the UI vocabulary, whose `default` is one —
declares that kind's `RecordFields` to keep its witness and `StructuralAccess`, and supplies
`MapMsg` to request `Derivation.MapMsg` and retire its hand-written map.

**Evidence.** `IdlDeriveTests`, "Phase 403 - a projected kind under the derivations": a vocabulary
projecting `Gate`, whose wire `rule` is optional where the record's `Rule` is required, emitted
with the map and the record declared and RUN under `dotnet fsi` (the walks, the rule slot, the
mapped handler and the encoding, line for line); the same probe over the pre-403 reading (the wire
fields taken as the record's) fails to compile with `FS0001`, so the probe tells the two apart; the
refusal with no map, with its unchanged message; each refusal with no declared record, by name;
the undeclared-type refusal; the support document's round trip; and the diff seeing either member.

### The public-surface gate draws the attributes that decide what consumer source is legal (Phase 406) — NO PACKAGE MOVES (the gate's own baseline format); a qualification is now a `retype`

**What changed.** A type in an `api/<package>.txt` baseline now carries one
`attribute <type> <Name>` line per attribute the F# compiler reads off it to decide which consumer
source compiles: `RequireQualifiedAccess`, `AutoOpen`, `NoEquality`, `NoComparison`,
`ReferenceEquality`, `AllowNullLiteral`, `Sealed`, `AbstractClass`, `Measure`, and `Struct` (read
off the IL: a type whose base is `System.ValueType`). On a type both sides publish, adding or
removing one of those lines is a `retype`, which is breaking, and the report prints what the move
costs a consumer beside it. On a new type the line is `additive`; on a type that left it goes with
the type as a `removal`. Phase 386's six qualifications read `unchanged` before this; they are now
classed moves (the 386 entry above points at each).

**What it costs a pinned consumer: nothing.** No package source changed. The one-time regeneration
moved 17 of the 18 baselines, adding 107 lines (103 `RequireQualifiedAccess`, 2 `NoComparison`, 1
`NoEquality`, 1 `Sealed`); `Fuaran.Core.Idl.Cli` carries no drawn attribute. Every moved line is an
`attribute` line, and each file with those lines removed is byte-identical to its predecessor.

**What is not drawn, and why.** `CustomEquality` and `CustomComparison` leave the type satisfying
`equality` and `comparison`; what changes is the result of `=`, a behaviour. `StructuralEquality` and
`StructuralComparison` assert the default. `CompilationRepresentation(ModuleSuffix)` renames the
module in IL, which the `type` line already shows. The member- and parameter-level attributes that
change call syntax or compiled shape — `ParamArray`, `[<Optional>]` and `?arg`, `[<Extension>]`,
`CompilerMessage`, `RequiresExplicitTypeArguments`, and any other `CompilationRepresentation` — are
carried nowhere on the shipped surface, so the family refuses them by name instead of drawing them:
the day one appears it is red, and the renderer learns to draw it in the same change.

**Against a tag cut before this phase.** The since-tag report compares without attribute lines when
none of the tag's baselines carries one, and prints that it did, the way Phase 237's field names
are handled. It expires at the first tag cut after this phase: that tag carries the lines.

**Evidence.** `PublicSurfaceTests`: every drawn attribute renders on a probe that carries it, and
the drawn set has a probe for each; the go-red pair (a union bare in one module and qualified in
another, compiled into the test assembly) classes the gain as one `retype` printing its reason, the
loss as one too, and an identical pair as unchanged, while the same pair without attribute lines is
unchanged (the pre-406 blindness); every drawn attribute added to or removed from a rendered type is
one `retype` with its reason; a planted `ParamArray` parameter and F# optional argument are named by
the refusal scan. DECISIONS.md D134.

### The public-surface gate marks static members (Phase 408) — NO PACKAGE MOVES (the gate's own baseline format); an instance/static flip is now a `retype`

**What changed.** IL leaves `this` out of a method's signature, so `member x.M(a)` and
`static member M(a)` rendered the same `method` token, and turning one into the other — which changes
every call site — read as `unchanged`. A static method, property or non-literal field of a type that
is not a module now ends its token with ` (static)`, the way a literal field ends with ` (literal)`.
The marker sits outside the member's identity, so a flip on a member both sides publish pairs into
one `retype`, and the report names the direction and what it costs a caller beside it. A module's
members carry no marker: each is static by construction, and its `type … (module)` line already
says so.

**What it costs a pinned consumer: nothing.** No package source changed. The one-time regeneration
moved 2 of the 18 baselines, marking 5 lines: `WireShape.Default`, `HardenPolicy.Undeclared` and
`Annotations.Empty` in `Fuaran.Core.Idl`, and `Gen.GenSupport.Empty` and `SupportDocument.Empty` in
`Fuaran.Core.Idl.Codegen`. Every moved line gained the marker and nothing else, and each file with
the marker removed is byte-identical to its predecessor. No other package declares a static member
on a type.

**Against a tag cut before this phase.** The since-tag report compares without the marker when none
of the tag's baselines carries one, and prints that it did, as Phases 237 and 406 do. Nothing is
hidden by that against `v0.36.0`: the same five members were static there, and no member has
flipped since. The strip expires at the first tag cut after this phase.

**Evidence.** `PublicSurfaceTests`: a probe type's static method and property carry the marker, its
instance property and a module's members do not, and the marker lies outside the identity; the
go-red pair (one method, an instance member in one module and static in another, compiled into the
test assembly) classes the flip as one `retype` printing its direction, the reverse flip as one too,
and an identical pair as unchanged, while the same pair without the marker is unchanged (the
pre-408 blindness); the since-tag reading strips the marker only for a tag none of whose baselines
carries it. DECISIONS.md D137.

### `SigEntry.Kind` is the `HoleKind` it projects (Phase 409) — `removal` on `Fuaran.Core.Function`, paid by the major; the capability reader refuses an entry without the member its kind needs; every well-formed capability document is byte-identical

**The class, from the gate.** The surface family, read against the baselines this phase started
from, prints `Fuaran.Core.Function` **`removal`** (9 moves): five `removal` (`HoleKind.tryOf`, the
`SigEntry.HoleKind` member, the `Space`, `Slot` and `Action` fields), three `retype` (the
`SigEntry` constructor, `Kind` from `string` to `HoleKind`, and `Required`'s position) and one
`additive` (the `SigEntry.Space` member). The wire family prints `Fuaran.Core.Function`
**`breaking`** against `v0.36.0`, for the reason under "The wire".

**What moved.** `SigEntry` is `{ Addr; Name; Kind: HoleKind; Required }`. A value or repeat hole's
space, a slot's constraint and an action hole's effect ceiling are read from `Kind`, so an entry
holds one copy of each and cannot carry a space or an effect its kind disagrees with (the defect
D104 named when it rejected this retype beside the fields). `SigEntry.Space` is a member that reads
the argument space from the kind: the space of a value or repeat hole, the `SlotTree` of a slot's
constraint, `None` for an action hole. It is what `Capability.validateArgs`, `Signature.validate`
and the schema projections read. `HoleKind.tryOf` and the `SigEntry.HoleKind` member, which
projected the four fields onto a kind, are gone: nothing is left for them to project. No public
record field in `Fuaran.Core.Function` carries a `string` over a closed set it declares.

**The reader.** `CapabilityCodec`'s entry reader reads an entry AS its hole kind. A `value` or
`repeat` entry without a `space`, and an `action` entry without an `actionEffect`, is refused
`MissingField` at that member (`signature.holes[i].space`, `…actionEffect`), wherever an entry is
read: `signatureOf`, the capability readers and every document that embeds a signature. Before this
phase the bare signature reader READ such an entry, as one of no hole kind, and the capability
reader refused it only as non-total, `OutOfRange` at `signature.holes`. A `slot` entry needs no
member; without `slotKind` it is the unconstrained slot, as before. A member the kind does not read
(a `space` on a slot, a `slotKind` on a value) is still read and refused when malformed, and is not
part of the entry.

**The wire.** Every document the writers produce is byte-identical: each kind writes exactly the
members it wrote before (`space` for a value or repeat, `slotKind` for a constrained slot, nothing
for an unconstrained one, `actionEffect` for an action), in the same order. The `Function` wire
baseline moves because its document set is generated from the types. It used to fill every field
of `SigEntry` at once, which gave one entry with tag `"s"` carrying all three members, a document no
writer produces. It now reaches each `HoleKind` case, so the baseline shows each kind's members and
its tag. The `breaking` class is that projection's honest reading of the change; no stored document
a `0.36.0` writer produced reads differently.

**The model.** `sig_entry` in `proofs/Capability.fst` carries the `hole_kind`, and `entry_space`
reads the space from it. `entry_total` is restated over the kind: every entry is a hole kind, so a
repeat over no count space is the one non-total entry. `entry_of_j` reads the members in production's
order and then the kind, refusing the missing member by name. `signature_roundtrip`,
`signature_roundtrip_identity`, `signature_decoded_wf` and `capability_roundtrip` lose their normal
form: every entry reads back as itself, so the round trip is the identity on every well-formed
signature, with no spaceless slot and no entry of no hole kind to except. Re-verified with
`check.ps1 -Modules Capability -Extract -Runs 3`: three cold runs (184s, 239s and 161s against the
290s budget, on a shared machine), every query 3/3 under `--quake`, at the pinned rlimit, on the
first iteration. The oracle is re-extracted, never hand-edited.

**Evidence.** `FunctionTests`, "the capability reader refuses an entry without the member its kind
needs, at that member": the `value`, `repeat` and `action` documents are refused `MissingField` at
`signature.holes[0].space` / `…actionEffect` by the capability reader and refused by `signatureOf`,
beside a control document that reads and an unconstrained slot that reads. The go-red, measured
against the tree this phase started from (DECISIONS.md D139), shows `signatureOf` reading all three.
The model's twins `a-value-entry-without-a-space-is-refused-at-space` and
`an-action-entry-without-its-effect-is-refused-at-actionEffect` state the refusal, and the codec
differential mutates every generated entry's kind payload away and holds production to the oracle
on each. A consumer's edit is in [the 1.0.0 migration](../migrations/1.0.0.md).

### A column carries typed vectors (Phase 417) — `removal` on `Fuaran.Core.Column`, paid by the major: `Column.Cells` and `Column.create` leave, `Column.Type` is derived; one additive family on `Fuaran.Core.Conformance`; every column wire byte unchanged; one law vector moves, and it is the representation leak closing

**The class, from the gate.** `api/Fuaran.Core.Column.txt` — **`removal`**: the record field
`Column.Cells`, the record field `Column.Type` (a derived property now) and `Column.create`; the
record constructor `retype`s to `(string, ColumnData)`. Additive beside them: `Vector<'T>` with its
`Vector` module and `Vector.Unsafe`, `Validity` with its module, the `ColumnData` union, and on
`Column` the typed builders, the typed readers, `validity`, `isPresent`, `ofCells` and `toCells`.
`api/Fuaran.Core.Conformance.txt` — **additive**: `columnVectorLaws`. `Fuaran.Core.Query` and
`Fuaran.Core.Validator` move nothing: their readers changed body, not surface.

**What changed.** A `Column` is `{ Name; Data }`. `Data` is one case of `ColumnData` per column type
— `Ints`, `Floats`, `Bools`, `Strs`, `Dates`, `Timestamps`, `Decimals` — each an opaque, immutable
`Vector<'T>` of values beside a `Validity` mask (`Vector<bool>`, `true` where the row is present), and
`Column.Type` is the case the storage carries, so a column cannot disagree with its own storage.
`Cell` stays the scalar read type: `Column.cell i c` is one mask read and one vector read, O(1) where
it walked a list, and `Null` for an absent or out-of-range row. A consumer that wants an int column's
storage reads `Column.tryInts c` and holds the `Vector<int>` itself — no conversion, no copy.

`Vector<'T>` is the contract, not a convention (the operator's ruling of 2026-10-09, DECISIONS.md
D142): no public member writes; `Vector.ofArray` copies, `Vector.adopt` takes ownership of an array
the caller promises not to touch again; `Vector.slice` is a view over the same storage; `toArray` is a
copy; and `Vector.Unsafe.borrow` is the one route to the backing array, under the written rule that the
borrower does not write. Equality and hashing are by element under the cell's float identity — every
NaN one value, `-0.0` equal to `0.0` — and `ColumnData` compares by its CELLS, the element under an
absent row taking no part. Phase 418 states the ownership contract in full and adds its law family.

**The bridge.** `Column.ofCells name ty cells : Result<Column, ColumnError>` and `Column.toCells`
replace `Column.create` and `.Cells`. `ofCells` REFUSES the first present cell whose type does not
widen into the column's, as the `TypeMismatch` `Table.validate` named for it before: the typed
storage cannot hold a `Bool` in an int column, so no column can, and `Table.validate`'s clause (e)
no longer has that case. A widened `Int` is normalised at construction — held as its float in a float
column and as its digits in a decimal column, exactly as decode already held it — and reads back as
the `Float` or `Decimal` it widened to. What the type CAN hold is held as found and refused where it
always was: a non-finite float and non-canonical decimal, date or timestamp text by `Table.validate`
(and so by `tryEncode`), a `Decimal` whose text is not decimal by `Column.aggregate`'s
`CellOutsideType`, which is now the only way that refusal arises. `Table.validate` gains one arm, a
`LengthMismatch` for a hand-built storage whose values and mask differ in length.

**The wire.** Unchanged for every column. `ColumnCodec.encodeJson` walks the vectors and writes the
absent slot at an absent row whatever the vector holds there; `decodeJson` builds each column's
storage straight from the `values` and `validity` arrays, by one typed reader per column type, with
the `Cell list` decoder's refusals in the `Cell list` decoder's order. The corpus families, the
`LawVectors` suite and the `WireColumn` oracle hold it.

**One law vector moves, and the acceptance said none would.** `decimal-laws.json`'s `aggregate-max`
(and the `ParityVectors` row `decimalAggregate/max`) answers `m:2` where it answered `i:2`. The
column is built from cells that include `Int 2`; the `Cell list` column kept that cell as an `Int` and
`Max` returned it as it stood, while decode of the same document already held it as the decimal `2`
and answered `m:2`. The typed column holds one value for both, so the vector pinned exactly the
representation leak this phase removes. Every other vector, row and wire byte is unchanged; the
declared copy `wire-format-fixtures/laws/decimal-laws.json` takes the same one-token re-stamp.

**The wire-surface baselines re-key, and the gate calls that breaking.** `api/wire/Fuaran.Core.Column.txt`
and `api/wire/Fuaran.Core.Query.txt` hold one exemplar document per union case a wire root reaches
through the TYPES. `Cell` is no longer reachable from `Column` — its storage is `ColumnData` — so the
`Cell.*` documents leave and `ColumnData.*` documents arrive, each column document now carrying one
present and one absent row where the `Cell.Null` document carried the absent slot alone. The
baseline's class line reads `breaking` because documents left the set; no canonical byte of a document
the codec writes for a given table moved, which is the claim the corpus families and the oracle hold.

**The oracle.** `ProofOracleTests`' bridge into `proofs/WireColumn.fst` reads production through
`toCells` and builds through `ofCells`; the model keeps its cell-list form. The wild generator no
longer draws a cell of another type (it is unrepresentable), so the model's clause-(e) `TypeMismatch`
is reached from production only through a column whose type differs from its schema entry; and the
valid pool's non-normal tables fall from 355 to 192 at the pinned seed, because an `Int` in a float
or decimal column is now normal at construction. Phase 419 restates the clause-for-clause claim as a
refinement theorem.

**Measured, for the design note (D142).** Under node (Fable 5, node 25), a summing loop over two
million floats reads 4.2–4.3 ns/element through the raw array, 4.4–4.5 through the class with an
offset, and 4.4–4.5 through a class holding the array alone — the class costs 3–8 % and the view's
offset nothing measurable; on .NET (Release) all three are 0.68–0.71 ns/element. `[<Erase>]` was
not a candidate: an erased type is its one field, so it can carry neither the slice's offset nor an
equality of its own, two of the four reasons the type exists.

**What a consumer edits** (Phase 424 carries the wave): `Column.create n ty cells` becomes
`Column.ofCells n ty cells` (a `Result`) or a typed builder; `c.Cells` becomes `Column.toCells c`,
`Column.cell i c`, or the typed reader; `{ c with Cells = … }` and `{ c with Type = … }` rebuild the
column. A `Column` or `Table` is no longer comparable (`Vector` has no order), only equatable.

### The `Vector` ownership contract, stated and certified (Phase 418) — `additive` on `Fuaran.Core.Conformance`: two law-family entry points; `Fuaran.Core.Column`'s surface unchanged; no wire byte, digest, law vector or `ParityVectors` row moves

**The class, from the gate.** `api/Fuaran.Core.Conformance.txt` — **`additive`**: `columnOwnershipLaws`
and `columnOwnershipLawsWith`. `api/Fuaran.Core.Column.txt` does not move: Phase 417 had already
shipped the mechanism this phase was written to add — `Vector.adopt`, `Vector.slice` as a view,
`Vector.Unsafe.borrow`, and no public member that writes — so the work here is the contract and its
check, not the type. Two doc comments grow (`adopt` and `Unsafe.borrow` name the family that catches
a broken promise); no signature changes.

**What is promised.** `STABILITY.md` ("The ownership contract of `Vector`") states it as a
stability-critical promise: no public member of the vector or the column layer writes into a
vector's storage, so its contents never change after construction except through an array handed
over with `Vector.adopt` or lent by `Vector.Unsafe.borrow`; every other constructor copies or builds
fresh; `slice` is a view, never a copy. `adopt` hands the caller a zero-copy construction and the
obligation never to touch the array again; `borrow` hands it the backing array with the range the
vector occupies, and the obligation not to write through it, inside the range or out of it. Changing
any of this is a major bump. It is not an F* theorem: the models carry no mutation.

**What checks it.** `Conformance.columnOwnershipLaws operation seed iterations` hands `operation` the
kit's sample each iteration — a column of each of the seven types over adopted arrays, nulls drawn,
and two float columns that are adjacent views of one backing array and one mask array — and
`Conformance.columnOwnershipLawsWith operation draw seed iterations` hands it the columns the
consumer's own `draw` builds, for a pipeline that wants its own schema. Each fingerprints every column
(SHA-256 over every element in the column's range, the element under an absent row included, and
over its mask; strings by their UTF-16 code units, so an unpaired surrogate is seen; floats by their
canonical text with the sign of zero kept), runs the operation, fingerprints again, and fails naming
the column whose bytes moved — `column 2 "g" (float): the bytes of its values moved` — with every
other column that moved in the same run. One assertion per column, so a draw that builds none reds
as never reached. One write it does not see, by design: one NaN over another, since a NaN's payload
is not portable across hosts. The family is compiled on both pipelines from shifts, masks and code
units, with nothing host-specific.

**What runs it here.** Core certifies its own column reads with it (every cell read, every aggregate,
the typed readers and every vector read, `Unsafe.borrow` read and not written, the cell bridge, the
table check and the codec both ways), and the go-reds in `ColumnTests.fs` write through a borrow
(named by column), run a borrowed write one past a view's end (named as the NEIGHBOUR's bytes, not the
view's), flip a borrowed mask bit (named as the mask), write an array after adopting it (red) and after
`ofArray` (green — the copy), and write under an absent row and `-0.0` over `0.0` (both writes, though
neither changes a cell). The slice test now also writes through the parent's borrow and reads the
change through the view, so "a view, never a copy" is observed rather than inferred from a reference.

**What a consumer edits:** nothing. A consumer that borrows or adopts adds one run of the family over
its pipeline.

### A null-free column carries no validity array (Phase 420) — `retype` and `removal` on `Fuaran.Core.Column`, paid by the major: `Validity` is `AllValid` or a `Mask`; no wire byte, digest, law vector or `ParityVectors` row moves

**The class, from the gate.** `api/Fuaran.Core.Column.txt` — **`retype`**: `Validity` was an
abbreviation of `Vector<bool>` and is now a two-case union, `AllValid | Mask of present: Vector<bool>`,
so every member that took or answered one is retyped — the seven typed builders (`Column.ofInts` …
`ofDecimals`), `Column.validity`, `ColumnData.Validity` and the seven `ColumnData` cases, and
`Validity.isPresent`, `ofArray` and `ofList`; `Validity.presentCount` gains the row count it needs
(`presentCount n v`). **`removal`**: `Validity.all n` leaves — its `n` had nothing left to describe,
and `AllValid` is the value it built. **Additive**: `Validity.ofVector`, `Validity.toMask` and
`Column.mask`. The wire-surface baselines (`api/wire/Fuaran.Core.Column.txt`,
`api/wire/Fuaran.Core.Query.txt`) are re-rendered: the reflection exemplar of a validity is now its
first case, `AllValid`, so the exemplar documents show an all-true validity array, and two per-case
documents are added — `Validity.Mask`'s is byte-identical to the exemplar the baseline held before.
No canonical byte the codec writes for a given table moved.

**What changes for a column.** A column with no absent row holds no mask at all: `AllValid` is one
shared value, so the `bool` per row and the vector around it are gone. The normalising constructors
— `Validity.ofArray` (over its copy), `Validity.ofList` and `Validity.ofVector` (over the vector it is
handed) — answer `AllValid` exactly when no bit is clear, an empty mask included, and `Column.ofCells`
and decode build through them, so every column Core builds is normal. A reader that needs a mask asks
for one: `Column.mask c` (or `Validity.toMask n v`) answers a `Mask`'s own vector uncopied and, for
`AllValid`, a fresh all-true vector of the column's length. `Validity.isPresent` reads every
non-negative row present under `AllValid`, which has no length, so `Column.isPresent` and
`Column.cell` now bound the index by the values first; for a well-formed column nothing moves, and
for a hand-built column whose mask is longer than its values a row past the values is now `Null`
where `cell` used to index past the end. `Table.validate` names `LengthMismatch` only for a `Mask`: an
`AllValid` column cannot disagree with its values. The codec writes an `AllValid` column's all-true
validity array directly, without materialising a mask, so the wire and the corpus are byte-identical.

**The design question, settled: both, with equality as the guarantee.** The shard left open whether
an all-true `Mask` and `AllValid` are one value under equality, or whether the builders normalise so
the second cannot exist. Normalisation alone cannot be the guarantee: `Mask` is a public case a
consumer can construct, so an all-true `Mask` CAN exist whatever Core's builders do. So column
equality is the guarantee — `ColumnData`'s equality compares the MATERIALISED masks
(`ColumnStorage.sameMask`, without materialising either): `AllValid` equals a `Mask` exactly when that
mask is all true and of the column's length, and hashes alike — and normalisation is the economy:
every column Core builds is `AllValid` when it can be, so the common case holds nothing. `=` on two
bare `Validity` values compares representations, because with no length `AllValid` has no mask to
compare; compare columns. `ColumnTests.fs` ("Column validity: AllValid or a Mask (Phase 420)") pins
both halves, `Conformance.columnVectorLaws` gains the pair per drawn type (an `AllValid` column and the
same values under a hand-built all-true `Mask` are one column hashing alike; a `Mask` one row longer
is not), and the refinement proves it: `proofs/ColumnRefinement.fst` section 7 models the two cases
and proves `AllValid` reads as the all-true mask of the column's length (`all_valid_reads_all_true`,
so an `AllValid` column is always well-formed), the normalising constructors lose nothing
(`of_mask_to_mask`, `of_mask_normal`), and `sameMask` is equality of the materialised masks at every
length (`same_mask_is_mask_equality`), each measured red under its own perturbation; the extracted
model is held to the shipped `Validity` by a differential with a go-red (the model comparing
representations loses on exactly the mixed equal pairs).

**Why `Mask` holds a `Vector<bool>`, not the shard's `bool[]`.** Phase 418 made the immutable
`Vector` the ownership contract: no public member writes. A `bool[]` in a public union case would be
a mutable array any holder of the column could write, outside that contract and out of the ownership
family's sight. As a `Vector<bool>` the mask is under it: copied by `ofArray`, held by `ofVector` and
the `Mask` case as handed (as the typed builders hold their values), lent only by `Vector.Unsafe.borrow`.
The ownership family fingerprints a `Mask` as before and reads an `AllValid` column's validity as a
fixed token — there is nothing to write into — and its kit sample now draws both cases.

### Temporal columns are integers, and timestamps carry a unit (Phase 422) — `retype` on `Fuaran.Core.Column`, paid by the major: `ColumnType.TimestampType` carries a `TimeUnit`, and `Dates` / `Timestamps` hold integers; three sub-second wire tags are admitted; every existing column byte, corpus vector and law vector is unchanged

**The class, from the gate.** `api/Fuaran.Core.Column.txt` — **`retype`**: `ColumnType.TimestampType`
gains its unit (`TimestampType of unit: TimeUnit`), so every match on it gains a pattern;
`ColumnData.Dates` holds `Vector<int>` (days since 1970-01-01) where it held `Vector<string>`, and
`ColumnData.Timestamps` is `unit * seconds: Vector<float> * fraction: Vector<int> option * validity`;
`Column.ofDates`, `Column.ofTimestamps`, `Column.tryDates` and `Column.tryTimestamps` (which answers a
`TimestampVectors` record) are retyped with them. **Additive**: `TimeUnit` and its module (`digits`,
`scale`, `ofDigits`, `widens`), `CivilDate`, `TimestampVectors`, the integer half of `TemporalText`
(`daysOfCivil`, `civilOfDays`, `tryDays`, `dateText`, `tryInstant`, `instantText`, `unitOf`,
`compareInstants`, `isDayInRange`, `isInstantInRange`, `MinDay`, `MaxDay`, `minSecond`, `maxSecond`),
and, on .NET only, `Column.tryDateOnly`, `Column.tryDateTimeOffset`, `Column.ofDateOnlys` and
`Column.ofDateTimeOffsets`. `ColumnType.all` APPENDS the three sub-second units after `DecimalType`, so
its earlier prefix and order stand. The decisions are DECISIONS.md D143.

**Behaviour that moves, each named.** (1) `Column.ofCells` REFUSES a `Date` or `Timestamp` cell whose
text is not canonical, with the `MalformedShape` `Table.validate` named for it: the integer storage
cannot hold it. `Table.validate` now checks the integers a hand-built column can get wrong (a day or a
second outside `0000`..`9999`, a second that is not whole, a fraction outside its unit's range, a
fraction vector of another length). (2) `Cell.compare` orders two `Timestamp` cells CHRONOLOGICALLY —
the minimal canonical text puts `…12.5Z` before `…12Z` as a string — and a text that is not canonical
after every canonical one; dates keep ordinal order, which is chronological for their fixed width. (3)
`Cell.typeOf (Timestamp s)` is the coarsest unit that holds `s`, so a seconds column refuses a
fractional instant (`TypeMismatch` naming `timestamp_ms` …) and a finer column admits a coarser one. (4)
A query's `Where` literal of a timestamp fits a column at least as fine as its own unit (an exact type
match before, which a unit would have made unusable); a literal whose text its column cannot hold is
still an `IllFormedLiteral`, now read from `Column.ofCells`'s refusal. (5) The query JSON-Schema
projection writes a per-unit pattern for a sub-second column; the seconds pattern is unchanged.

### A unit is a value (Phase 426) — a NEW package, `Fuaran.Core.Unit`: the runtime dimension algebra over a stated UCUM subset and ISO 4217 currencies, one canonical text per unit; no other package's surface, wire byte, digest, law vector or `ParityVectors` row moves

**The class, from the gate.** A new baseline, `api/Fuaran.Core.Unit.txt` — **`additive`** on the
packable set: `UnitOfMeasure` (a record with an internal representation), `Ratio`, `UnitRefusal` (eight
cases: `Empty`, `Malformed`, `UnknownAtom`, `Annotation`, `ArbitraryUnit`, `NonRatioUnit`,
`PrefixNotAllowed`, `NumericFactor`, each naming the token and its position), `UnitConversionRefusal`
(`Incompatible`), and the module `Unit` — `parse`, `render`, `dimensionless`, `mul`, `div`, `pow`,
`compatible`, `conversionFactor`. The module is `Unit` and the type `UnitOfMeasure`, because a type named
`Unit` would shadow F#'s `unit` in every file that opens `Fuaran.Core`. No project references;
FSharp.Core only. The design record is [docs/units.md](docs/units.md): the admitted vocabulary (the seven
SI base units with the gram, the twenty prefixes, the SI coherent derived units, a stated set of non-SI
and customary units, bracketed ISO 4217 currency codes each a dimension of its own), identity as the
canonical atom product rather than the denotation, the exact rational scale, and the refusal of affine
and logarithmic units outright so that `mul` / `div` / `pow` stay total.

**Behaviour.** `parse` is iterative (nesting never reaches the machine stack), reads the UCUM grammar
over the subset and refuses by class; `render` writes the canonical text — factors ordered by symbol then
prefix, numerators joined by `.`, each denominator as `/x`, the exponent magnitude without a sign, `1`
for the dimensionless unit; `parse (render u) = u` for every unit. Exponents are `int32`;
`mul` / `div` / `pow` raise `ArgumentException` past the range rather than wrap.

**Record and certification.** `STABILITY.md` ("The unit algebra") states what is guaranteed and what
class each change takes, written by Phase 427 (this phase stayed off Phase 417's files). `UnitTests`
holds the code to `docs/units.md`'s atom table row by row. The package is registered in the solution,
the README, the doc-coverage ratchet, the public-surface baselines, the Fable exclusions and the proof
coverage record (`model-scheduled`: its model is Phase 428's).

**What a consumer edits.** Nothing: the package is new. A consumer that needs units without columns takes
only `Fuaran.Core.Unit`.

### A schema entry is a `Field` that carries a unit and a description (Phase 427) — `retype` and `record-widening` on `Fuaran.Core.Column` and `retype` on `Fuaran.Core.Query`, paid by the major: `Schema` is `Field list`, the entry's metadata rides the wire absent-when-unstated; every existing column, delta and declaration byte, every law vector, fingerprint and `ParityVectors` row is unchanged

**The class, from the gate.** `api/Fuaran.Core.Column.txt` — **`retype`**: `Table.Schema`,
`Schema.diff`, `Schema.patch` and `Schema.fingerprint` take and answer `Field list` where they took
`(string * ColumnType) list`; `SchemaDelta.Added` and `Removed` are `Field list`. **`record-widening`**:
`SchemaDelta` gains `Amended: (string * FieldChange) list` (a full-literal construction of a delta names
it; `Schema.identityDelta` and `{ identityDelta with … }` do not move). **`retype`** on the union:
`SchemaError` gains `MetadataDisagrees of column * change`, so an exhaustive match gains an arm.
**Additive**: `Field` (properties `Name`, `Type`, `Unit`, `Label`, `Description`, `Ext`) and its module
(`create`, `withType`, `withUnit`, `withoutUnit`, `withLabel`, `withoutLabel`, `withDescription`,
`withoutDescription`, `withExt`, `withoutExt`, `hasMetadata`), `FieldChange` (`Unit`, `Label`,
`Description`, `Ext`), `Table.tryField`, `ColumnCodec.fieldJson` and `ColumnCodec.decodeField`.
`api/Fuaran.Core.Query.txt` — **`retype`**: `Query.ResultSchema` is a `Field list`. `Fuaran.Core.Column`
now references `Fuaran.Core.Unit` (the dependency runs Column → Unit, never the reverse). The
wire-surface baselines are re-rendered: the exemplar schema entry now carries the four metadata members
(the unit specimen is `kg`), and no canonical byte the codec writes for a given table, delta or
declaration without metadata moved. The decisions are DECISIONS.md D144.

**Behaviour that moves, each named.** (1) A schema entry on the wire — a table's `schema`, a delta's
`added` / `removed`, a declaration's `resultSchema` — carries `unit` (canonical text), `label`,
`description` and `ext` (an object of strings) when the field states them, and nothing when it does not,
so an existing document is byte-identical and a pre-427 reader reads past the new members. (2) Decode
reads a parseable unit spelling to the unit (`s-1.m` re-encodes as `m/s`, `l` as `L`) and REFUSES a text
the algebra does not parse as `MalformedShape` naming the column, the text and the class; a non-string
`unit` / `label` / `description`, a non-object `ext` and a non-string `ext` member are refused the same
way. (3) `Schema.diff` reports a metadata change as `Amended`, one entry per member that moved, beside a
retype; `Schema.patch` replays it and refuses one computed against another schema
(`MetadataDisagrees`); the delta wire gains `amended` only when non-empty. (4) `Schema.classify` reads a
depended-on column's stated unit replaced or withdrawn as `Breaking`, a unit stated afresh, a label or a
description as compatible, and an extension change on a depended-on column as `Unknown` — the first
production of that case. (5) `Schema.fingerprint` is unchanged over a schema without metadata and moves,
injectively, with metadata. (6) `Table.validate` reads no metadata; a `Column` still carries its name and
storage only, and `Table.tryField` reads its field by name. (7) The query codec's result column is the
column codec's schema entry; the strict reader admits the four members.

**Certified.** `ColumnTests` "Column fields: unit, label, description and extensions (Phase 427)" (seven
cases: builders and readers, identity, the round trip and the pinned pre-427 bytes, decode's
canonicalisation and refusals, the delta and its replay, the verdicts, the fingerprint and its
injectivity); the codec round-trip law's generator and the Phase 317 delta generator now draw metadata;
`QueryTests` carries a declaration whose result field states every member through both codecs and the
registry; `queryLaws` states metadata on its result field one iteration in three, so the Phase 302
result-binding law and both codec round trips carry it; and a third law-vector family,
`conformance/laws/field-laws.json` (`fieldLaws`, 43 authored vectors over five cases), beside the two
existing files, which are re-emitted byte-identical. The corpus side of that family — the copy and its
`laws/manifest.json` row — is an edit in the corpus repository, declared in `copies.json`.

**What a consumer edits.** A schema literal `[ "a", IntType ]` becomes `[ Field.create "a" IntType ]`;
