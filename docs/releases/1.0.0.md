## 1.0.0 — DRAFT

The first major. It opens over the released `0.36.0` and is the one slot where a removal is free:
the `0.x` line's scheduled removals land here, and from this slot the version is semver
([`STABILITY.md`](../../STABILITY.md), "Versioning policy"). A consumer's edits, from any `0.x`
pin back to `0.20.0`, are [the 1.0.0 migration](../migrations/1.0.0.md).

### A kind projection carries its message map and declares its record's fields (Phase 403) — BREAKING-SOURCE: `Gen.KindProjection` gains `MapMsg` and `RecordFields` (`record-widening`); the support document gains two optional keys (`additive`); an emission over a projected kind that cannot read its record now refuses

**The class, from the gate.** The surface family prints `Fuaran.Core.Idl.Codegen` **`record-widening`**:
`Gen.KindProjection` gains the record fields `MapMsg: string option` and
`RecordFields: IdlField list option`, so its constructor is a `retype` and every full-literal
construction of a projection stops compiling (`FS0764`) until it names both. The wire family prints
the `supportArtifact` baseline **`additive`**: a projection may now carry `mapMsg` and
`recordFields`, and a projection declaring neither renders byte for byte as it did, so every
existing `support.json` reads unchanged under encoding version 1. No other baseline, wire byte or
committed generated module moves.

**Why.** A kind projection (`Gen.KindProjection`) replaces a kind's record, encoder and decoder with
host source. The generator then has no way to know the record's shape, yet three emissions read it:

- `Derivation.MapMsg` refused a vocabulary with a projected kind ("the message map over the
  projected kind …"), and a projection had no member through which a host could supply the one
  piece the generator cannot construct. A host with a projected kind kept a hand-written message
  map beside its otherwise generated layer — the walk a new kind can be missed by.
- `Derivation.SlotsOf`, the node witness (`children` / `withChildren`, private or under
  `StructuralAccess`) and `KeyedPositions` read the kind's WIRE fields as if they were the
  record's. Where the two differ — a wire key optional where the record's member is required, two
  wire keys merged into one member — the emission did not compile: a host's `SlotsOf "Binding"`
  produced `match s.On with Some …` against a required `On` (`FS0001`). A generator that emits
  source that does not compile is a defect, not a limitation.

The design, the refusal rules and the rejected alternatives are DECISIONS.md D132.

**What moved, for a consumer.**

- **`KindProjection.MapMsg`** — the full `and private mapMsg<Tag>Spec<'Msg, 'Msg2> (f: 'Msg -> 'Msg2)
  (v: <Tag>Spec<'Msg>) : <Tag>Spec<'Msg2> = …` member, verbatim, written once in host source beside
  the record as `Mk` already is. `Derivation.MapMsg` joins it to the derived message map's
  recursion group, so it may call `mapMsg f` and every derived `mapMsg<Decl> f`. With `None`, the
  refusal stands with the same construct, principle and alternative: the generator does not guess a
  map.
- **`KindProjection.RecordFields`** — the projected record's fields at their HOST shapes (name as a
  wire field is spelled, the member being its PascalCase; type; optionality). The witness, the keyed
  walk and the slot enumerators read these in place of the kind's wire fields. A declared field at a
  type the module does not declare is refused by name ("the projected record field 'Gate.owner' at
  the undeclared type 'Owner'").
- **With `RecordFields = None`, an emission that would read the record refuses by name** instead of
  emitting source that may not compile: the node witness and `StructuralAccess` when the kind's wire
  holds a node directly ("the node witness's children of the projected kind …"), `KeyedPositions`
  when it holds one anywhere ("the keyed node positions of the projected kind …"), and `SlotsOf`
  always ("a slot enumerator over 'T' through the projected kind …"), because a record may hold a
  value of the type that its wire spells otherwise. A projected kind whose wire holds no node still
  emits a plain module with no declaration: a node on no wire key is a node no host reads back, so
  the record holds none.
- **`support.json`** carries the two members as `mapMsg` and `recordFields` on a projection entry,
  the fields in `idl.json`'s own field shape (one codec for both documents), and `Diff` compares
  both as part of the projection's support entry.

**Adopting it.** Name both members in every full-literal `KindProjection` (`MapMsg = None;
RecordFields = None` keeps today's emission wherever no refusal above applies). A host whose
projected kind's wire holds a node — `Switch` in the UI vocabulary, whose `default` is one —
declares that kind's `RecordFields` to keep its witness and `StructuralAccess`, and supplies
`MapMsg` to request `Derivation.MapMsg` and retire its hand-written map.

**Evidence.** `IdlDeriveTests`, "Phase 403 - a projected kind under the derivations": a vocabulary
projecting `Gate`, whose wire `rule` is optional where the record's `Rule` is required, emitted
with the map and the record declared and RUN under `dotnet fsi` (the walks, the rule slot, the
mapped handler and the encoding, line for line); the same probe over the pre-403 reading (the wire
fields taken as the record's) fails to compile with `FS0001`, so the probe tells the two apart; the
refusal with no map, with its unchanged message; each refusal with no declared record, by name;
the undeclared-type refusal; the support document's round trip; and the diff seeing either member.

### The IDL command writes UTF-8 whatever the console code page (Phase 407) — no surface change

`fuaran-core-idl` now sets its standard output and standard error to UTF-8 without a byte-order mark
before its first write, so the usage heading's em dash and any non-ASCII text in a report reach a
pipe as the same bytes on every machine, where the encoding had followed the console's code page.

### The public-surface gate draws the attributes that decide what consumer source is legal (Phase 406) — NO PACKAGE MOVES (the gate's own baseline format); a qualification is now a `retype`

**What changed.** A type in an `api/<package>.txt` baseline now carries one
`attribute <type> <Name>` line per attribute the F# compiler reads off it to decide which consumer
source compiles: `RequireQualifiedAccess`, `AutoOpen`, `NoEquality`, `NoComparison`,
`ReferenceEquality`, `AllowNullLiteral`, `Sealed`, `AbstractClass`, `Measure`, and `Struct` (read
off the IL: a type whose base is `System.ValueType`). On a type both sides publish, adding or
removing one of those lines is a `retype`, which is breaking, and the report prints what the move
costs a consumer beside it. On a new type the line is `additive`; on a type that left it goes with
the type as a `removal`. Phase 386's six qualifications read `unchanged` before this; they are now
classed moves (the 386 entry above points at each).

**What it costs a pinned consumer: nothing.** No package source changed. The one-time regeneration
moved 17 of the 18 baselines, adding 107 lines (103 `RequireQualifiedAccess`, 2 `NoComparison`, 1
`NoEquality`, 1 `Sealed`); `Fuaran.Core.Idl.Cli` carries no drawn attribute. Every moved line is an
`attribute` line, and each file with those lines removed is byte-identical to its predecessor.

**What is not drawn, and why.** `CustomEquality` and `CustomComparison` leave the type satisfying
`equality` and `comparison`; what changes is the result of `=`, a behaviour. `StructuralEquality` and
`StructuralComparison` assert the default. `CompilationRepresentation(ModuleSuffix)` renames the
module in IL, which the `type` line already shows. The member- and parameter-level attributes that
change call syntax or compiled shape — `ParamArray`, `[<Optional>]` and `?arg`, `[<Extension>]`,
`CompilerMessage`, `RequiresExplicitTypeArguments`, and any other `CompilationRepresentation` — are
carried nowhere on the shipped surface, so the family refuses them by name instead of drawing them:
the day one appears it is red, and the renderer learns to draw it in the same change.

**Against a tag cut before this phase.** The since-tag report compares without attribute lines when
none of the tag's baselines carries one, and prints that it did, the way Phase 237's field names
are handled. It expires at the first tag cut after this phase: that tag carries the lines.

**Evidence.** `PublicSurfaceTests`: every drawn attribute renders on a probe that carries it, and
the drawn set has a probe for each; the go-red pair (a union bare in one module and qualified in
another, compiled into the test assembly) classes the gain as one `retype` printing its reason, the
loss as one too, and an identical pair as unchanged, while the same pair without attribute lines is
unchanged (the pre-406 blindness); every drawn attribute added to or removed from a rendered type is
one `retype` with its reason; a planted `ParamArray` parameter and F# optional argument are named by
the refusal scan. DECISIONS.md D134.

### The public-surface gate marks static members (Phase 408) — NO PACKAGE MOVES (the gate's own baseline format); an instance/static flip is now a `retype`

**What changed.** IL leaves `this` out of a method's signature, so `member x.M(a)` and
`static member M(a)` rendered the same `method` token, and turning one into the other — which changes
every call site — read as `unchanged`. A static method, property or non-literal field of a type that
is not a module now ends its token with ` (static)`, the way a literal field ends with ` (literal)`.
The marker sits outside the member's identity, so a flip on a member both sides publish pairs into
one `retype`, and the report names the direction and what it costs a caller beside it. A module's
members carry no marker: each is static by construction, and its `type … (module)` line already
says so.

**What it costs a pinned consumer: nothing.** No package source changed. The one-time regeneration
moved 2 of the 18 baselines, marking 5 lines: `WireShape.Default`, `HardenPolicy.Undeclared` and
`Annotations.Empty` in `Fuaran.Core.Idl`, and `Gen.GenSupport.Empty` and `SupportDocument.Empty` in
`Fuaran.Core.Idl.Codegen`. Every moved line gained the marker and nothing else, and each file with
the marker removed is byte-identical to its predecessor. No other package declares a static member
on a type.

**Against a tag cut before this phase.** The since-tag report compares without the marker when none
of the tag's baselines carries one, and prints that it did, as Phases 237 and 406 do. Nothing is
hidden by that against `v0.36.0`: the same five members were static there, and no member has
flipped since. The strip expires at the first tag cut after this phase.

**Evidence.** `PublicSurfaceTests`: a probe type's static method and property carry the marker, its
instance property and a module's members do not, and the marker lies outside the identity; the
go-red pair (one method, an instance member in one module and static in another, compiled into the
test assembly) classes the flip as one `retype` printing its direction, the reverse flip as one too,
and an identical pair as unchanged, while the same pair without the marker is unchanged (the
pre-408 blindness); the since-tag reading strips the marker only for a tag none of whose baselines
carries it. DECISIONS.md D137.
