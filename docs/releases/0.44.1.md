## 0.44.1 — DRAFT

**Slot class: additive.** The patch after the released `0.44.0`. It opens over `v0.44.0`, which is a consumer's
contract, so nothing rides it; the work in this slot is additive, which makes it a PATCH slot, and a member of a
higher class advances it to the `0.45.0` minor rather than riding it ([`STABILITY.md`](../../STABILITY.md),
"Versioning policy"). The performance review wave, Phases 608 to 616, opens it. The conformance `kitVersion` stamp
lines move to `0.44.1` with the slot, and the corpus pin moves to the re-stamp of the declared copies.

### Additive

### Internal

- **A column with no absent row allocates no mask while it is built** (Phase 608, `Column.fs`) — no package
  surface, wire byte or refusal moves. `TypeOps.fill`, the walk under `Column.ofCells` and the codec's decode,
  allocates the validity mask at the first absent row, with the rows before it present, and answers `AllValid`
  holding no array when none is absent; a timestamp column's two vectors are filled directly, without the pair
  array copied out of before. Measured in `benchmarks/results/2026-11-19-ultra9-386h-phase-608.md`: a ten-cell
  `Column.ofCells` plus `Column.aggregate` allocates 14 % less, and a null-free 100,000-row timestamp decode
  1.7 MB less, with fewer gen2 collections.
- **A digest copies its input once** (Phase 609, `Fuaran.Core.Text`) — class **internal**: no `api/` or `api/wire/`
  row, no verdict and no vector moves. `Hash.utf8Bytes` sizes one exact array with `utf8ByteCount` and encodes into
  it; the SHA-256 compression reads every whole block straight from its input and pads only the tail in a 64- or
  128-byte scratch; the hex form writes one `char[64]`. `sha256Hex` over a million mixed units allocates 1.36 MB
  where it allocated 9.63 MB, and `sha256HexOfBytes` a constant 728 bytes at every size where it allocated three
  times its input; measured in `benchmarks/results/2026-11-19-ultra9-386h-phase-609.md`.
- **A store load finds its lines in place** (Phase 610, `Fuaran.Core.OpStream`) — `Jsonl.scanRecords` finds each line
  by `IndexOf('\n')`, a `\r` before the `\n` taken as the terminator, and copies each line once, where it rewrote the
  text with `\r\n` read as `\n` and split it. A CRLF text is no longer copied whole: over a 30 MB, 9,844-line store
  the CRLF scan allocates 182.7 MB where it allocated 243.7 MB, and gen2 falls from 0.91 to 0.19 per load; an LF text
  was never copied whole and is unchanged. The lines, their numbers and every refusal and its position are the
  split's, held against the old scan by a sweep. No API, wire byte or conformance file moves.
  ([results](../../benchmarks/results/2026-11-19-ultra9-386h-phase-610.md))
- **`Dag.heads` and the drain allocate no whole-DAG lists** (Phase 614, `Fuaran.Core.OpStream.Dag`) — class
  **internal**: no `api/` row, wire byte, order or refusal moves. `Dag.heads` gathers parents into a `HashSet` and
  reads the node map in its own ordinal key order, with no lists, `Set` or sort; the Kahn drain keeps in-degrees and
  children in `Dictionary`s sized to the node count and keeps the ordered `Set` frontier that defines the order.
  Over a 9,866-node store `Dag.heads` allocates 0.20 MB where it allocated 8.33 MB, `Dag.totalOrderBy` 4.2 MB where
  it allocated 33.8 MB, and `Dag.tryReplayTo` 18.8 MB where it allocated 48.4 MB, with gen2 per call unchanged.
  Held against the previous walks, kept verbatim, over hand-built DAGs with cycles.
  ([results](../../benchmarks/results/2026-11-19-ultra9-386h-phase-614.md))
- **A parse copies no number or literal token on .NET** (Phase 616, `Json.fs`, with the grammar's range form in
  `JsonSyntax.fs`) — class **internal**: no `api/` row, wire byte, refusal kind, sentence or position moves. The
  scanner holds a number token to the grammar where it stands in the input and reads it there, `TryParse` over a
  span and the int53 bound and float layout compared ordinally in place; `true`, `false`, `null` and the tolerant
  read's member-`null` look-ahead are compared in place too; the integer read answers a `ValueOption`. The Fable
  build keeps its one `Substring` per token. A parse of the 10,000-float corpus allocates 0.97 MB where it allocated
  1.50 MB, 10,000 integers 0.83 MB where 1.41 MB, and 10,000 literals 0.82 MB where 1.14 MB; measured in
  `benchmarks/results/2026-11-19-ultra9-386h-phase-616.md`.
- **A date or an instant renders into one string** (Phase 611, `TemporalText.fs`) — class **internal**: no `api/`
  row, wire byte or refusal moves. `dateText` and `instantText` write a day or an instant in the canonical range into
  one `char[]` sized to the text and build one string from it, over the civil parts the date accessors share; a day,
  a second of the day or a fraction outside the range keeps the padded text it always had, held against that form by
  new tests at every unit. `dateText` allocates 96 bytes where it allocated 180, `instantText` 128 to 171 where 364
  to 468, and a cell read of a 100,000-row date column 12.8 MB where 21.2 MB; measured in
  `benchmarks/results/2026-11-19-ultra9-386h-phase-611.md`.
- **An aggregate over a date, a timestamp or a bool compares the carrier** (Phase 612, `Column.fs`) — class
  **internal**: no `api/` row, answer, wire byte or refusal moves. `Min` and `Max` compare a bool column's bools, and
  a date or timestamp column's day counts, or seconds and then fractions, when every present value is in the
  canonical range, rendering only the answer; `CountDistinct` keys the same values. A column holding a day or an
  instant outside the range keeps the rendered cells, where text order and day order disagree. `Max` over a
  100,000-row millisecond timestamp column allocates 208 bytes where it allocated 59.8 MB, and `CountDistinct` over
  it 8.5 MB where 31.4 MB; measured in `benchmarks/results/2026-11-19-ultra9-386h-phase-612.md`.
- **The slot paragraph names each class that advances the slot** (Phase 698, `open-slot`, DECISIONS.md D269) — class
  **internal**: no `api/` or `api/wire/` baseline moves, and no package, wire or conformance byte. The sentence that
  `open-slot` writes about what advances a slot is built from `expectedOver`: each class whose version over the newest
  release lies past the slot's is named, with the version it advances the slot to. An internal PATCH slot on the `0.x`
  line now reads "a breaking member advances it to the `0.N+1.0` minor", where it read "a member of a higher class",
  which an additive member rides. The advance paragraph names the classes that do not ride the draft the same way. A
  test holds every slot and every advance the act admits to `expectedOver`. Released notes keep the sentence they
  were written with, and this slot's own paragraph is not regenerated (D269.3).
