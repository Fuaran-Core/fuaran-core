## 0.44.1 — DRAFT

**Slot class: additive.** The patch after the released `0.44.0`. It opens over `v0.44.0`, which is a consumer's
contract, so nothing rides it; the work in this slot is additive, which makes it a PATCH slot, and a member of a
higher class advances it to the `0.45.0` minor rather than riding it ([`STABILITY.md`](../../STABILITY.md),
"Versioning policy"). The performance review wave, Phases 608 to 616, opens it. The conformance `kitVersion` stamp
lines move to `0.44.1` with the slot, and the corpus pin moves to the re-stamp of the declared copies.

**Each entry of this slot is a file of its own** (DECISIONS.md D274): add one as
`docs/releases/0.44.1/<class>/<name>.md`, with `<class>` one of `breaking`, `additive` or `internal` and `<name>`
`phase-<n>` (`phase-<n>-<word>` for a phase's second entry) or `pr-<n>`, holding the entry's bullet exactly as it
will print, and the act that closes the slot renders the entries here, a section per class.

- **The claims ladder gains a fifth assumed class, `witness-obligation`** (Phase 601, `proofs/kit/`, `proofs/`) —
  class additive; no package, wire or conformance surface moves, and every existing ladder reads as before. A
  `witness-obligation` row is a property every implementation of a domain's own witness must answer, which a theorem
  takes as a hypothesis and the witness's own tests discharge: no law of the shipped kit reaches it, so it is neither
  a `domain-obligation` nor a `host-premise`. It names the member in `dischargedBy`, `<Witness>.<member>`, and its
  `evidence.assumption` says what the member answers. `Proofs.Ladder` refuses such a row with no `dischargedBy`, with
  one outside that form or naming a `Conformance.<law>` (that row is a `domain-obligation`), and with a `closes` or a
  `probe`; `Proofs.Coverage` counts it as `witness-discharged`. The ladder summary and the contract section count the
  class (this repository's ladder carries none), the kit template carries one annotated example row, and the kit
  asset's sha moves with `LADDER.md` and the template. **Migration:** none for a package consumer. A ladder that
  already carries rows of this class decodes unchanged once a registry reads the kit at this version, whether or not
  its rows name a `dischargedBy`: a registry refuses only an unrecognised `class`, and the member rule is held by the
  host family of the repository that states the rows.
- **A parse holds its nesting cap on any thread stack** (Phase 663, `Json.fs`, DECISIONS.md D272) — class
  **internal**: no `api/` row, wire byte, refusal kind, sentence, position or path moves. The `JVal` parse keeps its
  open containers in a list indexed by nesting level, in the heap, where it recursed once per container, so the cap
  is reached and refused by name whatever the stack. The recursion spent 576 to 1,280 bytes of stack a level, so on
  a 256 KB thread a document at the default cap of 512 ended the process in Release and Debug builds alike, where
  the cap promises `MaxDepthExceeded`; it now decodes there, the one past it is refused, and a lifted cap decodes
  100,000 levels. The container rules are steps the reader's loops and the parse both run, so there is still one
  copy of each. A parse of 2,000 five-member objects allocates 1.44 MB where it allocated 3.03 MB, and every other
  case about 210 bytes more; time reads within the noise of the machine. Measured in
  `benchmarks/results/2026-11-19-ultra9-386h-phase-663.md`.
- **A host's adoption record moves when the family or the host's answers change** (Phase 703, DECISIONS.md D273;
  `docs/conformance-corpus.md`, the adoption-record section; a comment in `ApplyVectorExport.fs`) — class
  **internal**: records and documents only; no `api/` or `api/wire/` row, conformance byte, manifest, corpus file or
  corpus pin moves. A record moves at first adoption, when the family's vectors change and the host measures them,
  and when what the host's leg answers changes; never when the host's pin moves over unchanged vectors or a leg
  changes how it reports. The Rust port's eleven records naming `0.41.0` or `0.43.0` stay: each family's vectors are
  the same blob at the tag its record names and at `v0.44.0`, and a `kitVersion` older than the host's pin reads
  that the family has not changed since. `skeletonMerge` and `skeletonDiff`, restamped four times over unchanged
  vectors and an unchanged leg, are recorded as the exception and are not moved back.
