### Additive

- **`CorpusFile` is public: the one writer of a shared-corpus conformance file** (Phase 543, `Fuaran.Core.Conformance`;
  DECISIONS.md D210, amending D171) — class additive. `CorpusFile.render`, `CorpusFile.firstDifference`,
  `CorpusFile.str`, `CorpusFile.num` and the types `CorpusCell` (`Value` / `Row` / `List`, qualified access),
  `CorpusDocument` and `CorpusDifference` become public, for a producer outside this repository to write its corpus
  files with the writer every Core exporter uses and hold its committed copies with the same freshness reading. The
  compute producer adopts it against this release. `CorpusDifference.Committed` and `Rendered` are `string option`
  (`None` past a text's end) where the internal record carried the string `<absent>`. The manifest schema
  (`CorpusManifest`, `CorpusManifestRow`) stays internal. No wire byte and no committed conformance file's bytes move;
  the bytes `render` writes are now a stability-critical surface (`STABILITY.md`).

### Internal

- **The corpus's shared `apply/manifest.json` is declared as the index this repository owns a row of, not as a copy**
  (DECISIONS.md D211) — no package surface, wire byte or committed conformance byte moves. `copies.json` drops its
  `conformance/apply/manifest.json` record, which the workspace copy sweep read stale forever because the corpus file
  carries other producers' families beside `skeletonApply`. The projection registry declares it `rowIn`, the exporter
  table names the files each writer merges into (`SharedIndexes`), the `Projections` family refuses a shared index
  declared as a copy (and a whole file declared as a row), and the apply family's corpus-freshness leg holds the row.
- **The extracted models run as a process a host's fuzzer can query** (Phase 482, `fuaran-core-oracle`; DECISIONS.md
  D208) — class additive; no package surface, wire byte or proof byte moves. The extracted models are served as a
  process over the versioned JSON-lines oracle protocol 1.0 ([`docs/oracle-protocol.md`](../oracle-protocol.md)):
  `json.parse`, `wire.decode`, `wire.render`, `tree.apply`, `chain.verify`, `dag.fold`. It is released as one
  self-contained binary per platform, plus `fuaran-core-oracle-<Version>.sha256`, attached to the `v<Version>`
  GitHub release. It is not a package and adds no nuget.org id. The publish workflow gains `oracle-build`,
  `oracle-smoke` and `oracle-release`, and `ci.yml` gains `oracle-smoke`.
