**0.5.0 (2026-08-21).** `Hash` gains the pinned pure SHA-256 — `sha256Hex` over a string,
`sha256Bytes` / `sha256HexOfBytes` over arbitrary bytes, and the `utf8Bytes` encoder they
hash through. Purely additive: `fnv1a` and `foldSep` are byte-identical and merely moved
into their own file, so every stored content hash is unchanged and consumers repin without
source changes. MINOR rather than patch because a new public function in a shipped module
is a contract a consumer can pin against, and because this reverses a stated posture —
STABILITY.md previously said no cryptographic hash ships in Core. See DECISIONS.md D15.
