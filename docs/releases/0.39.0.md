## 0.39.0 — DRAFT

The minor after the released `0.38.1`. It opens over `v0.38.1` and carries the slices of the 2026-10-17
redesign pass. Through the `0.x` line a breaking class rides a minor ([`STABILITY.md`](../../STABILITY.md),
"Versioning policy"), and this slot opens on one: a renderer that now refuses a value it used to write.

### Breaking

- **The canonical writer and the IDL encoder refuse a repeated member name** (Phase 495, `Fuaran.Core.Wire`,
  `Fuaran.Core.ContentAddress`, `Fuaran.Core.Idl`) — the third refused class, which `Json.tryRender` and
  `Canon.tryRender` have refused since Phase 462 (`0.38.1`, under Breaking on the same footing).
  `Canonical.tryWrite`, and so `ContentAddress.ofValue`, now refuse a value carrying one member name
  twice; before, they digested text that `Json.parse` refuses, so an address could name bytes no reader
  accepts. `Idl.Encode.encode` and `encodeOp` refuse a map value, or a verbatim json value, that carries
  one key twice, naming the key and its path; before, they wrote wire that `Decode.decode` refuses. No
  public signature changes and no wire byte moves for any value that was readable before.
  **Migration:** a caller that built such a value was already producing text no reader accepts; build the
  value with one member per name, or handle the refusal the call now returns.
- **The query seam's two policy refusals carry their seam on the wire** (Phase 497, `Fuaran.Core.Query`).
  `QueryError.QueryPolicyRefused` and `QueryApprovalRequired` encoded to `$type` `policyRefused` and
  `approvalRequired`, the tags of the capability seam's `InvokeError.PolicyRefused` / `ApprovalRequired`,
  with the same members, so a refusal document did not say which seam refused and each seam's reader
  accepted the other's (measured: all four cross-readings decoded). The query seam's tags are now
  `queryPolicyRefused` and `queryApprovalRequired` (the case-name prefix D101 gave the cases, carried onto
  the wire); the capability seam's are unchanged; `QueryError.describe` is unchanged; and each reader
  refuses the other seam's tags as an unknown `$type`. The `api/wire/Fuaran.Core.Query.txt` rows move.
  A policy refusal is raised before the resolver runs and is never captured, so no keyed-capture journal
  holds one. **Migration:** a consumer that reads query-seam refusal documents matches the new tags; one
  that wrote them writes the new tags.
- **`ColumnValidator.ofType` reports the column, not its cells** (Phase 497, `Fuaran.Core.Validator`) — a
  verdict change. The rule read each present cell's type back from its text, and a millisecond (or finer)
  timestamp column renders a whole-second instant with no fraction, which reads back as seconds: every
  such row of a column OF the declared type was a `COL-OFTYPE` error. Since Phase 417 a present cell is
  always of its column's type, so the rule now answers the one fact it can: a column whose type is not
  the declared one is ONE `COL-OFTYPE` error located at the column (its name, not `column#row`); a column
  of the declared type reports nothing, and a column of another type is reported even with no present
  row (the cell walk had nothing to read there). Measured before the fix: a millisecond column with two
  whole-second rows reported two errors. The code, the severity, the message's form (`got` now names
  the column's type) and the rule id are unchanged. **Migration:** a caller counting `COL-OFTYPE` findings per row, or reading their `#row`
  location, reads one finding at the column.

### Additive

- **A base-aware footprint, and the arbitration and fold entries that hold the base** (Phase 500,
  `Fuaran.Core.Ops`, `Fuaran.Core.OpStream.Dag`, `Fuaran.Core.Conformance`; D166). `Ops.footprintIn` /
  `footprintInKeyed` compute a script's footprint at the tree it applies to, threaded op by op: a removal
  or a move names its source parent as a known structure-write, a removal content-writes the subtree it
  destroys, a move reads its destination's ancestors, an in-place `UpdateNode` reads and content-writes
  its target alone, and an absent target — or any op after one that does not apply — takes the pure
  arm, so the result is never less conservative than `Ops.footprint` where the tree is silent. Two
  in-place edits of different nodes under different parents are independent; an edit beside the
  removal of its ancestor is not. `Arbitration.arbitrateIn`, `Dag.conflictsIn`, `Dag.reconcileIn` and
  `Dag.reconcileManyIn` compose it (the last two replay the shared region before reading a footprint,
  since that is the state the exclusive deltas apply to); `Conformance.footprintInLawsAt` certifies
  soundness, refinement of the pure projection and determinism at a domain's own ops. Proved:
  `FootprintIn.footprint_in_refines` (no pair the pure footprint frees is refused) and
  `footprint_in_sound` over every operation, moves included (the five move pairs were proved in the
  phase's continuation, on the facts that each edit distributes over a graft elsewhere and that a move
  keeps every other node, parent and path in place). The pure entries and every verdict they give are
  unchanged; no public signature changes.

- **The op-stream packages are total where their facade says so** (Phase 496, `Fuaran.Core.OpStream`,
  `Fuaran.Core.OpStream.Dag`). Four throw sites are gone: the single-op appends return the record they
  chained rather than matching it back out of a list (`appendIfWith` / `appendIf`, `appendIdempotent`,
  `appendIdempotentIf`), and `Dag`'s JSONL loads build the decoded DAG in the pass that collects the
  refused nodes. All three were unreachable and nothing a caller sees moves. The fourth was reachable:
  `captureEffectKeyed` over a journal holding a settlement with no attempt before it, at the occurrence
  the next attempt takes, threw `failwithf "unreachable …"`; it now journals the attempt and its
  settlement and answers the live outcome, and the journal still fails `verifyKeyedCaptures` as it did
  before (the two-step `beginEffectKeyed` / `settleEffectKeyed` refuse the same input as
  `AlreadySettled`, unchanged). `Conformance.keyedCaptureLaws` gains the law, built every iteration. No
  public signature changes.
- **Stated limits, with go-red fixtures, no code change** (Phase 496, `Fuaran.Core.Ops`, `Fuaran.Core.Tree`).
  `WriteGate`'s subtree rule reads ancestors along the structural walk, so a lock on a holder does not
  reach a node in its keyed positions; `Diff` has no keyed form, and `Tree.traversal` is not a witness
  to diff over (its shells break the keyed arity). Both are stated in the module headers and pinned by
  `KeyedGateDiffTests`.
- **`Tree.Index` gives one answer to a repeated id** (Phase 496, `Fuaran.Core.Tree`): `tryBuild` refuses
  the tree with `Tree.wellFormed`'s verdict, `isFreshFor` certifies no index of it as fresh, and `build`
  is the lenient builder, total by signature, keeping the LAST occurrence as `Tree.digests` does; its doc
  now says so. Measured: no caller outside Core reads `Tree.Index.build` (the hosts that index trees keep
  indexes of their own), and inside Core `Ops.Index.afterOp`'s fallback and its `afterOp ≡ build` law read
  its total signature. **Pending for a breaking cut:** `build` takes `tryBuild`'s semantics behind its own
  name, returning a `Result`, and `Index.path`'s cycle guard goes with it where `rebind`'s contract allows.
  Until then a caller that may meet a malformed tree builds with `tryBuild`.
- **One stamp heads every generated artefact, and it is a content hash, not a version** (Phase 505,
  `Fuaran.Core.Idl.Codegen`). The eight header grammars (the F# module's, which named the package
  version; the TypeScript module's and declarations', which named frozen phase labels; the three F*
  targets'; the scaffold's provenance header) are one renderer: `GENERATED by Fuaran.Core.Idl.Codegen —
  <target>`, a `vocabulary: sha256:…` line (the canonical `idl.json` value) and an `emission: sha256:…`
  line over every byte below the stamp (`docs/idl-stability-classes.md`, "The generated-artefact stamp").
  A release that emits the same bytes no longer re-stamps a consumer's committed modules. No public
  signature moves; every generated artefact's header text does, once. **Migration:** regenerate each
  committed generated module once after adopting this version; its drift guard then reads only real
  change. A test that compared two emissions byte for byte compares them below the stamp.
- **`STABILITY.md`'s footprint section names the six address sets** and the clauses they feed (the
  section said four since Phase 340), and its pinned over-approximation list gains the reorder arm's
  child reads and the move arm's target content-write, each kept under DECISIONS D162.
- **The conformance kit's record of itself is corrected** (Phase 498, `Fuaran.Core.Conformance`).
  `keyedArbitrationLawsAt` labels its adequacy guard with its own id; it handed the shared internal
  `keyedArbitrationLawsWith`'s, so a census keyed on the label read the `At` family's starvation under
  another row. The guard's law text moves (`sample adequacy (Conformance.keyedArbitrationLawsAt): …`); no
  verdict, count or JSON export byte does. The suite's guard-label check now holds each label to the family's own
  id or a delegate its census row declares (`(delegates to <entry>)`), where any roster id passed before.
  `docs/conformance-families.json` has a reader outside this repository, which keys on `kind` and reads
  `families[].id` and `families[].cases`; the source called every `schema` bump free on the claim that it
  had none, and `STABILITY.md` now carries the entry a bump must revisit (held by a test to the current
  `schema: 5`). The generated families document names the compute strand's package as
  `Fuaran.Compute.Conformance` (the `Fuaran.Core.DataFrame.Conformance` id stopped at `0.34.0`), and the
  `Module` member's documentation lists the seven modules of the current roster. No public signature
  changes; `Families.fs` is packed, so the package fingerprint moves.

### Internal

- **The xorshift32 kernel moved from `Fuaran.Core.Idl` to `Fuaran.Core.Wire`** (Phase 495) and
  `Corpus.fuzzRoundTrip` draws from it. It is internal, read by `Fuaran.Core.Idl` and
  `Fuaran.Core.Conformance` through Wire's friend grant; the Idl-to-Conformance grant is removed. Under
  node the old generator drew a near-constant sample (6 distinct values where .NET drew 1,579 over the
  same 2,000 draws); two new parity rows, `fuzz/sample/seed-1` and `fuzz/sample/seed-299`, hold the two
  hosts to one sample. No public surface moves.
- **`Propagation`'s header names the `evalFrom` trio as it is** (Phase 497): the columnar one left with the
  compute strand under D66, and the capability-DAG one stayed, as `CapabilityPipeline.evalFrom` in
  `Fuaran.Core.Function`; the header and the driver's banner said both had left. Comments only.
- **Every tag-reading family reads the release tags in HEAD's history, through one reader** (Phase 499,
  the test project; a gate behaviour, not a surface). The release record read `git tag --list --merged
  HEAD` while the package roster, the README's per-release claims, the 1.0 laws and the public and wire
  since-tag reports read `git tag --list`, so on a branch behind the newest tag the families disagreed
  about which tag was newest (Phase 475's red runs). All six now read `ChildProcess.Tags.released`:
  plain `vX.Y.Z` tags in HEAD's history, so "since the newest tag" means since the newest tag this tree
  descends from. `GateProbeTagTests` holds the reader to the probe tag and to HEAD's history. A clone
  with no release tag in its history fails the release-record and package-roster tag checks by
  design, as CONTRIBUTING.md now says. Two held artefacts of the IDL spike suite, `MiniGenerated.fs`
  and `snapshots/spike.json`, fail when absent instead of skipping. No baseline moves.
- **Two packed descriptions and the adoption guide say what is true** (Phase 499). The
  `Fuaran.Core.Ops` description names the skeleton ops with `UpdateNode` (an op since `0.32.0`); the
  `Fuaran.Core.Wire` description calls the decode layer portable, as it has been since D8, not
  ".NET-guarded". `docs/ADOPTION.md`'s dataframe section cites the README for the compute packages'
  ids and namespaces instead of restating the pre-`0.36.0` ones. Package metadata and prose only.
- **The proof leg has one roster, and the models share one list algebra and one twin record**
  (Phase 504, `proofs/`). `proofs/modules.json` is the roster: each entry carries a `kind` (`extracted`,
  `proofOnly`, `generated` or `shared`) and an `opens` list, in check order. `proofs/check.ps1` reads it and
  no longer carries a module literal, and the test families read it too: the ladder, the twin roster
  (found by reflection over the oracle), the oracle project's `Compile` list and the cone selector.
  `proofs/ListAlgebra.fst` (`app`, `mem`, `len`, `rev`, `distinct`, `inter`, `diff`) and `proofs/Twin.fst`
  (the twin record and `twins_hold`) replace the private copies in the models, and the cone reads a
  change to either as a shared input (DECISIONS D102, amended). The oracle is re-extracted. No package
  surface moves; the kit's caller and roster templates follow, and `copies.json` declares them.
- **The claims ladder says what each row does not cover, and every proof-leg run leaves one verdict
  record** (Phase 522, `proofs.json`, `proofs/`). Every ladder row carries `statement` and `boundary`,
  with its history cut to its `phase` citation and `claim` kept as their exact join for registries that
  still read it; a tested row's `family` is closed to `Proofs.Oracle`, `Conformance.<law>` or
  `Suite:<Module>.<list>`, and its cases are looked for in that suite. `Proofs.Ladder` gains four clauses
  (statement-boundary, claim-is-the-join, tested-family-closed, evidence-exists) and holds `supporting`
  names to the model, as `proofs/kit/LADDER.md` always said. The kit engine's `-SummaryFile` writes a run
  verdict (`kind: proofRunVerdict`) on every exit, green or red; `check.ps1` keeps the last at
  `proofs/obj/last-run.json`, `proofs/last-strict.json` is the same record of a green strict full run,
  and the strict workflow summarises from it. The floors' and contention's explanation lives once, in
  the engine's header. No package surface moves; the kit's engine, its refusal tests and three
  templates follow, and `copies.json` declares them.
- **One child-process runner, one tag reader and one repository root across the test project, and a
  tagless clone skips the tag legs instead of failing** (Phase 502, the test project; a gate behaviour,
  not a surface). `ChildProcess.run` is the one spawn site. It reads both pipes at once, with UTF-8
  pinned, so a child that fills one pipe cannot block the reader of the other. Thirty spawn sites now
  go through it: six hand-written git bodies (Phase 499 removed the seventh), three `pwsh` runs and
  twenty-one `node` / `dotnet` runs. A source sweep is red on a spawn anywhere else. `Repo.root` and
  `Repo.mainTree` replace seven climbs to the repository root, two ancestor walks and the corpus
  resolver's own main-tree anchor. `GateProbeTagTests` is red on a second tag reader.
  It also holds the tagless-clone contract, which replaces the Phase 499 reading above. A clone holding
  no `vX.Y.Z` tag reads as "no released tag", and every tag-reading family skips it by name. A clone
  holding release tags while HEAD's history contains none of them stays red.
  `CONTRIBUTING.md` says both, and says that a baseline-class report reads "since the newest tag in
  this branch's history". No baseline moves.
