## 0.43.0 — DRAFT

**Slot class: breaking.** The minor after the released `0.42.0`. It opens over `v0.42.0`, which is a consumer's
contract, so nothing rides it; through the `0.x` line a breaking class advances the MINOR, which makes it a MINOR
slot, and every later member rides it ([`STABILITY.md`](../../STABILITY.md), "Versioning policy"). Phase 635 opens
it. The conformance `kitVersion` stamp lines move to `0.43.0` with the slot, and the corpus pin moves to the
re-stamp of the declared copies.

### Breaking

- **The registry's gate takes a decision context, and a dispatch may present a grant** (Phase 638,
  `Fuaran.Core.Function`, `Fuaran.Core.Query`, `Fuaran.Core.AiSurface`, `Fuaran.Core.Conformance`; DECISIONS.md
  D249) — class breaking (removals: every member naming `PolicyGate`, `RegistryPolicy`, `Seam`, `CapabilityRegistry`,
  `FunctionRegistry`, `CapabilityLookup` or `PolicyDenial` moved its signature). A gate's `Decide` reads a context, a
  type parameter of those types, and each dispatch and `decide` takes the context and a `Grant option` after the
  registry; a pipeline run takes the context and a `Grant list`. A grant is bound to
  `Capability.invocationPreimage`, the injective pre-image with no hash taken, and lifts exactly one
  `NeedsApproval`; `Capability.invocationKey` is unchanged. `PolicyGate.ignoringContext` carries an existing gate
  across unchanged, and `CapabilityRegistry.under` fixes a context. What is guaranteed and the migration follow.

  **This is a source break.** A gate decides under a decision context, and a dispatch may present a
  grant (DECISIONS.md D249). The context is a type parameter of `PolicyGate`,
  `RegistryPolicy`, `Seam`, `CapabilityRegistry`, `FunctionRegistry` and `CapabilityLookup`, and every
  dispatch and `decide` takes the context and a `Grant option` after the registry. The surface class is
  **breaking** (removals: every member that named one of those types moved its signature), and it
  rides the standing `0.43.0` slot, which is a breaking slot already.

  **Guaranteed, and proved in `proofs/Capability.fst`:**

  - The join stays monotone under every context, and adding a gate never lowers a decision for any
    context (`policy_join_monotone_in_context`, `with_gate_tightens_in_context`).
  - A dispatch whose gates answer `NeedsApproval` runs its body exactly when it presents the grant for
    its own invocation. With no grant, or a grant for any other capability or any other arguments, it
    is `ApprovalRequired` and no body runs (`approval_dispatches_iff_granted`,
    `grant_for_another_invocation_refused`).
  - A `Deny` is lifted by no grant, an `Allow` is changed by none, and an id the registry does not
    hold is refused whatever is presented (`deny_reaches_no_performer`,
    `allow_unchanged_by_any_grant`, `unregistered_refused_whatever_presented`).
  - A grant is bound to `Capability.invocationPreimage`, which is injective with no hash in it
    (`invocation_identity_injective`). It is **never** bound to `Capability.invocationKey`, whose last
    field is a 32-bit cache hash. `invocationKey` and every journal keyed under it are unchanged.

  **Not guaranteed, because it is the host's:** who minted a grant, that it is used once, when it
  expires, and which generation of a registry it was minted against. Core reads no clock and keeps no
  count. A host states those as facts in the decision context, and a gate that reads them answers
  `Deny` for a grant that is spent or stale.

  **Migration, for an implementer of a gate.** A gate that does not read the context changes one line:

  ```fsharp
  // before
  let gate = { Policy = "limit"; Decide = fun cap args -> decide cap args }
  // after
  let gate = PolicyGate.ignoringContext "limit" decide
  ```

  It decides exactly as it did, under every context. A gate that should read the context is written
  `{ Policy = "limit"; Decide = fun ctx cap args -> ... }`, and the registry is then a
  `CapabilityRegistry<YourContext>`. A registry that needs no context is a `CapabilityRegistry<unit>`.
  A denial observer reads the context the refusal was made under from `PolicyDenial.Context`. A seam
  built on `Seam.create` adds `Invocation` to its vocabulary: the invocation's identity, which must be
  injective, so not a hashed key.

  **Migration, for a caller of dispatch.** Pass the context and the grant after the registry:

  ```fsharp
  // before
  CapabilityRegistry.dispatch registry id args body
  CapabilityRegistry.decide registry id args
  CapabilityPipeline.eval lookup spell body pipeline
  // after, with no context and no approval
  CapabilityRegistry.dispatch registry () None id args body
  CapabilityRegistry.decide registry () None id args
  CapabilityPipeline.eval lookup () [] spell body pipeline
  // after, presenting an approval for exactly this invocation
  CapabilityRegistry.dispatch registry ctx (Some(Capability.grant cap args)) id args body
  ```

  `FunctionRegistry.dispatch` and `decide`, `dispatchWithArgs`, `dispatchCaptured`, `dispatchReplayed`
  and `CapabilityPipeline.evalFrom` take the same two arguments in the same place.
  `Proposals.decideGuarded`, `submitGuarded` and `approveGuarded` take the context after the registry.
  The conformance witnesses hold a `CapabilityRegistry<unit>`: a host whose registry reads a context
  hands them `CapabilityRegistry.under ctx registry`. `QueryRegistry` keeps its verbs; only the type of
  the gate it takes moved, to `PolicyGate<unit, Query, _>`, and `PolicyGate.ignoringContext` builds one.

  The other-language ports and the consumers of the registry follow at their own raise.

- **The IDL gains the wider data universe** (Phase 639, `Fuaran.Core.Idl`, `Fuaran.Core.Idl.Codegen`;
  DECISIONS.md D251) — class breaking (`IdlType` gains eight cases, and `Fuaran.Core.Idl.Codegen`'s internal
  printers follow; a closed union gaining a case breaks every exhaustive match over it). `TInt64`, `TDecimal`,
  `TBytes`, `TTuple`, `TKeyedMap`, `TSet`, `TTimeOfDay` and `TDuration`, each with ONE canonical JSON spelling
  that every reader holds alone ([`docs/idl-wider-data-universe.md`](../idl-wider-data-universe.md)); a set and
  a keyed map's keys stand in ascending code-point order of their canonical texts, distinct. `idl.json` spells
  them `int64`, `decimal`, `bytes`, `tuple`, `keyedMap`, `set`, `timeOfDay` and `duration`, and refuses
  `localDateTime` as `NotAdmitted` with its reason. `ScalarText` is new: the five spellings and the canonical
  order, public. `IdlValue` and `HostedFormat` gain nothing: a value of a new type is carried in its wire shape
  (`VStr` text, `VList` items). Every generator binds each type (F# `int64`, `byte[]`, a tuple, `Set`, `Map`,
  and `string` for the exact text-borne types; TypeScript `bigint`, `Uint8Array`, a tuple and arrays),
  emitting its helpers only into a module whose vocabulary reaches one, so no other module moves a byte. The
  conformance vectors are `conformance/idl/wider-universe.json`.

  **Migration, for a consumer that matches on the IDL's types.** An exhaustive `match` over `IdlType` adds
  eight arms; the compiler names each site (FS0025):

  ```fsharp
  | TInt64 | TDecimal | TBytes | TTimeOfDay | TDuration -> (* a JSON string in its one spelling *)
  | TTuple components -> (* a JSON array, one item per component *)
  | TSet element -> (* a JSON array, canonical order, no repeat *)
  | TKeyedMap(key, value) -> (* a JSON array of [key, value] pairs, canonical key order *)
  ```

  A walker that recurses into a type's children (as `TList` and `TMap` do) recurses into a tuple's components,
  a set's element, and a keyed map's key and value. A host value of a set or a keyed map is authored in any
  order; the encoder writes the canonical one. No other surface moves, and a vocabulary that declares none of
  these types encodes, decodes, samples and generates byte for byte as before.

- **A capability declares its result** (Phase 642, `Fuaran.Core.Function`, `Fuaran.Core.Conformance`; DECISIONS.md
  D253) — class breaking (`Capability` gains a field, so every full-literal construction breaks; `Capability.create`
  takes the result; `FunctionEntry` loses its `ResultType` field, which is now a member derived from the
  capability; `FunctionRegistry.entry` takes the capability alone; `PipelineError` and `DeclarationFault` gain
  cases, declared last). `Returns` is what a capability answers: `Returns.Value` a value space, or
  `Returns.Nothing`, the one spelling of "returns nothing", written on the wire as `{"$type":"nothing"}`. The
  capability document gains the required member `result`; a declaration without it is refused `MissingField` at
  `result`. A result space the admission gate refuses is `IllFormedCapability` with `EmptyResult` or
  `NonFiniteResult` at `register`, and `OutOfRange` at `result` on read. A pipeline `Invoke` node's declared
  output must admit the capability's result (`Space.subsumes`), and a capability that answers nothing is no
  pipeline node: either is `PipelineOutputContradicts`, by name, at `typeCheck`. The capability law vectors
  (`conformance/laws/capability-laws.json`) carry `result` and the two new refusals; the seam-refusal vectors
  carry the two fault tags. The corpus copy and its `laws/manifest.json` row (96 vectors to 144, the stamp
  unchanged) are re-emitted by the same render, and the corpus pin moves to that commit (Phase 661).

  **Guaranteed, and proved in `proofs/Capability.fst`:** a pipeline `typeCheck` accepts invokes every capability
  at its declared result (`typecheck_invokes_at_declared_result`); a function registry entry's result kind, and
  the index a query narrows through, are its capability's declared result (`registry_result_is_capability_result`);
  a registry admits no ill-formed result (`register_refuses_ill_formed_result`).

  **Migration, for a consumer that constructs a capability.** Declare what it answers:

  ```fsharp
  // before
  Capability.create "score" sg Server
  { Id = "score"; Signature = sg; Placement = Server }
  // after: a value in a space
  Capability.create "score" sg Server (Returns.Value(FloatRange(0.0, 1.0)))
  { Id = "score"; Signature = sg; Result = Returns.Value(FloatRange(0.0, 1.0)); Placement = Server }
  // after: a call made for its effect, which answers nothing
  Capability.create "notify" sg Server Returns.Nothing
  ```

  **Migration, for a consumer of the function registry.** The kind an entry produces is its capability's result:

  ```fsharp
  // before
  FunctionRegistry.entry "Document" cap
  // after
  FunctionRegistry.entry { cap with Result = Returns.Value(SlotTree(Some "Document")) }
  ```

  `entry.ResultType` is now a `string option`, `None` for a capability that answers no tree of a named kind; such
  an entry is found by a query naming no result type. A pipeline whose `Invoke` declared an output its capability
  does not answer is refused: declare the capability's result, or a space that admits it. An exhaustive match over
  `PipelineError` adds `PipelineOutputContradicts`, and one over `DeclarationFault` adds `EmptyResult` and
  `NonFiniteResult`. The other-language ports follow at their own raise.

### Additive

- **The reader exposes a number's token text, and a lossless document model sits beside `JVal`** (Phase 640,
  `Fuaran.Core.Wire`; DECISIONS.md D252) — class **additive** (the `Fuaran.Core.Wire` baseline gains 72 members and
  loses none; it rides this slot). `Reader.numberText` reads a number token as its text, through the scanner
  `Json.read` runs and under its limits, so a host whose numbers keep their digits and scale reads them through
  the one grammar. `JDoc` is a document Fuaran does not define, held losslessly: `DNull`, `DBool`, `DNum` (the
  token text: `412000.00` and a thirty-digit integer as written), `DStr`, `DArr` and `DObj` (members in authored
  order). `JDoc.read` reads one through `Reader` and refuses exactly where `Json.read` does but for the nulls and the
  numbers `JVal` cannot hold; `JDoc.tryWrite` writes it compact, refusing a number text outside the grammar, a lone
  surrogate and a repeated member name at their paths; `JDoc.toJVal` converts by `Json.read`'s own number rule,
  refusing a null (`NotAdmitted`) and a number `Json.read` refuses (`OutOfRange`) at the path, and `JDoc.ofJVal`
  refuses only a non-finite float. `JDocDecoder` is the decode algebra over a document (`field`, `optField`, `at`,
  `list`, `tagDispatch`, `closed`, … with the `Decoder` refusals at the same paths), with `nullable`, `numberText`
  and `ofDecoder`, which reads a document with any `Decoder`. Proved: reading a document, then converting it, is
  the strict parse on every input (`proofs/JsonDocument.fst`, `lossless_reader_rebuilds_the_parse`), and a sound
  decoder reads a document through `ofDecoder` refusing only at paths that resolve in it (`of_decoder_is_sound`).

  **Nothing to migrate.** `Json.read`, the readings that build `JVal`, both null policies and every refusal are
  unmoved, and every `Decoder` combinator keeps its signature and its compiled arity (the combinators are now one
  algebra over a value carrier, instantiated at `JVal`). A consumer that kept its own parser for JSON with nulls or
  long numbers can read through `JDoc.read` instead.

- **The guarded witness gains a state-aware form** (Phase 643, `Fuaran.Core.AiSurface`, `Fuaran.Core.Conformance`;
  DECISIONS.md D254) — class **additive** (the `Fuaran.Core.AiSurface` baseline gains 29 members and loses none;
  `Fuaran.Core.Conformance`'s does not move; it rides this slot). `StateAwareGuardedWitness` sits beside
  `GuardedSurfaceWitness`, which is unchanged: the same surface and dry run, and an effects-of that takes the state
  the op would be applied to. Frozen at birth. `StateAwareGuardedWitness.ofGuarded` lifts a present witness into it.
  `Proposals.decideGuardedIn`, `submitGuardedIn` and `approveGuardedIn` decide over it: the dry run is walked and each
  op is decided at the state it would be applied to, before anything applies; a parked op keeps the invocations it was
  decided with (`Proposals.StagedOp`); an approval walks the dry run again at its own state, refuses the proposal as
  stale when an op's invocations moved (`Proposals.StagedApprovalFailure.StaleEffects`), decides each covered
  invocation through the gate with its grant, and answers those grants for the host's dispatches beside the queue
  and the state (`Proposals.StagedApproval`).
  `Conformance.policyLaws` gains six laws over the kit's own note-list reference domain. No rendered vector moves.

  **Nothing to migrate.** `submit`, `approve`, `submitGuarded`, `approveGuarded`, `decideGuarded`, every witness and
  every outcome type decide and construct as before. A domain whose operations are messages builds the new witness,
  or lifts its present one, and calls the `…In` verbs.
