### Breaking

- **A per-kind table declared in the support record, emitted as a total lookup** (Phase 689,
  `Fuaran.Core.Idl.Codegen`, DECISIONS.md D278) — class **breaking**: `record-widening` on `GenSupport` and
  `union-widening` on `Derivation`; no wire byte moves, and a vocabulary and support document that declare no table
  emit byte for byte as before. `KindTable` is new, a union whose case is the column (`Text`, `Bool`,
  `OptionalField`, `Texts` or `Enum`), with `GenSupport.KindTables` (table name to `KindTable`) and
  `Derivation.KindTable <name>` beside it. The F# module prints each requested table in a `KindTables` module as one
  exhaustive match over its kinds, with no wildcard arm. Generation refuses a missing, unknown or duplicate row,
  naming the table and the kind; the TypeScript backend refuses the request by name. `support.json` reads and writes
  the tables as `kindTables`, absent when empty, at encoding version 1. **What breaks, and what a consumer adds:**
  `GenSupport` gained a field, so a full-literal construction of it fails with FS0764 until it adds
  `KindTables = Map.empty` (one built as `{ GenSupport.Empty with … }` compiles unchanged); `Derivation` gained a
  case, so an exhaustive `match` over it is incomplete until it adds a `Derivation.KindTable _` arm.
- **A vocabulary's docs reach its JSON Schema** (Phase 704, `Fuaran.Core.Idl.Codegen`) — class **breaking**
  (behavioural): no `api/` or `api/wire/` row moves, and a vocabulary that documents nothing emits byte for byte as
  before; for one that does, `Gen.jsonSchema` and `Gen.contractArgumentSchemas` (whose `$defs` are the same
  definitions) answer different bytes. A declaration's `doc` annotation is the `description` of its definition (an
  enum, a union and every instantiation of a generic one, a record, a kind, an op), ahead of its keywords; a union
  case's is the `description` of its branch; a field's is the `description` of its property, after the keywords that
  state its type, the node envelope's members included. An enum case, an inline record and a presence-keyed union have
  no object of their own and carry none; their fields' docs still reach the members they lay out. A generic union stays
  defined once per instantiation under its instance names (`Binding_float`, `Binding_list_SelectOption`), the names a
  hand-written schema already publishes for the same definitions, so no second naming rule is added. **What a consumer
  does:** one that holds a documented vocabulary's generated schema to a fresh generation regenerates it; a
  description changes no document's validity.
- **The generated `NodeKind` cases and `Node` fields carry their docs** (Phase 705, `Fuaran.Core.Idl.Codegen`) —
  class **breaking**: no public signature moves, and the generated F# of a vocabulary whose kinds carry a `doc`
  annotation moves, so a consumer holding its generated module to a fresh generation regenerates it. Each
  `NodeKind` case carries its kind's authored doc, where only the kind's `<Kind>Spec` record did; the case takes the
  doc alone, and the deprecation, in-process and since notes and the `Obsolete` attribute stay on the spec record.
  The support record's `Docs` reaches three new paths: `case:NodeKind.<Tag>` above a case, `field:Node.Id` and
  `field:Node.Kind` above the node's identity and kind fields, which the IDL does not declare as fields, and
  `field:Node.<Field>` above an envelope field, as every record field takes one. A support block and an authored doc
  on one case are printed as Phase 713 prints them on any member. A node with no envelope and no node doc keeps its
  one-line record; one with a doc on `Id` or `Kind` is printed as a record of lines. **What a consumer does:**
  regenerate a committed generated module whose kinds carry a `doc`; a vocabulary that declares no doc emits the
  bytes it did, and a support document that names none of the new paths is unchanged (each was refused as a path the
  emission never consulted).
- **`RuleFamily` is opaque behind constructors, and per-node families share one walk** (Phase 709,
  `Fuaran.Core.Validator`, DECISIONS.md D279) — class **breaking**: the surface guard reads `removal` (the record's
  constructor and its `Id` and `Run` fields) beside two additions, `Validator.wholeTree` and the `Id` property. No
  finding moves: `Validator.runAll` and `runAllTagged` give the same findings in the same order (family order, then
  preorder) and the same one `RULE-FAULT` per throwing family, and they now run every per-node family of a registry
  over one preorder of the tree (at 5,021 nodes and 30 families, 4.8 MB a call where it was 18.9 MB;
  `benchmarks/results/2026-11-20-ultra9-386h-phase-709.md`). The stock `containment`, `referenceIntegrity` and
  `referenceOrder` families are built with `wholeTree` and find what they found. **What breaks, and what a consumer
  writes instead:** a record literal `{ Id = i; Run = f }` becomes `Validator.wholeTree i f`, and a read
  `family.Run w root` becomes `(Validator.asCheck w family).Run root`; `Validator.perNode` and `family.Id` are
  unchanged. `docs/ADOPTION.md` (section 3b) shows the two forms side by side. A later family shape is a new
  constructor, so it will not break a consumer's source again.
- **The profile bump answers major on a decided wire break, whatever else is undecided** (Phase 710,
  `Fuaran.Core.Idl.Codegen`, DECISIONS.md D242 as amended) — class **breaking**, behavioural: no signature and no
  wire byte moves, and an existing caller receives a different answer. For a verdict holding a decided
  `breaking-wire` row beside an undecided one, `Diff.bumpProfile` and `Diff.bumpProfileUnder` (under either decode
  rule) answered `Bump.Undecided rows` and now answer `Bump.Bumped` with the major moved, which is what the
  verdict's own `ProfileAdvice` already said; the undecided rows stay in `Verdict.Undecided`. A verdict whose only
  doubt is an undecided row, or whose undecided row stands beside an emitter break or an addition, still answers
  `Bump.Undecided`. `Diff.verdictClass` (and so the CLI's exit code) and `Verdict.StabilityImpact` are unchanged.
  **What a consumer does:** a caller that read `Bump.Undecided` as "no profile can be named" for such a verdict now
  receives the major to publish; one that still wants to hold it until the undecided rows are checked reads
  `Verdict.Undecided`, or the class.
- **A capability invocation keys its arguments by qualified hole name** (Phase 712, `Fuaran.Core.Function`,
  DECISIONS.md D281) — class **breaking**: `removal` on `Fuaran.Core.Function` and a breaking rewrite of its wire
  baseline. An argument binds the hole whose qualified name it carries. The qualified name is the names of the
  slots the hole was composed through, outermost first, then its own name, joined by `.`; it was keyed by the
  hole's address before.
  - **Holes and the admission gate.** `HoleDecl` gains `Slots: string list`, and `SigEntry.Name` is the qualified
    name. `Signature.validate` refuses a name outside the segment grammar (`IllFormedHoleName`; a segment is one
    or more ASCII letters, digits, `_` or `-`) and two holes with one qualified name (`DuplicateHoleName`); both
    are appended to `DeclarationFault`. `EmptySpace` and `NonFiniteBound` carry the name.
  - **The seam and its documents.** Validation, typing, invocation, `invocationKey`, `invocationPreimage`,
    `grant`, both registries and a pipeline's invoke node bind by name, and `Function.toJsonSchema` keys its
    properties and `required` by name. An invocation's argument is `{"name","value"}` and a pipeline argument
    is `{"name","source"}`; every seam refusal carries `name` (`names`) where it carried `addr` (`addrs`).
    `Capability.repeatedAddrs` is `repeatedNames`, `FunctionRegistry.narrow` takes names,
    `FunctionRegistry.addressed` re-keys an argument list to addresses for `Function.apply`, and `ContentPack`'s
    `BoundAddrs` and `UnknownBoundAddr` are `BoundNames` and `UnknownBoundName`. `apply`, `curry`, `compose` and
    `bindHandlers` still bind by address.
  - **The vectors** of `capabilityLaws`, `capabilityDocumentLaws`, `capabilityGateLaws` and `seamRefusals`
    (now 145 vectors) are re-emitted keyed by name, and the corpus pin moves with them.
  - **What breaks, and what a consumer changes:**
    - A full-literal `HoleDecl` fails with FS0764 until it sets `Slots`; a composing domain records slot names in
      its `Bind` and reports them in `Holes`.
    - An exhaustive `match` over `DeclarationFault` needs the two new arms.
    - A caller sends names, and an old `addr`-keyed invocation is refused `MissingField` at `args[i].name`.
    - A host codec reads and writes `name` members.
    - A declaration whose names repeat or break the grammar is refused where it was admitted.
    - A capture keyed before this change is keyed differently after it.
- **An enum or a union that declares no case is refused at its declaration** (Phase 713, `Fuaran.Core.Idl` and
  `Fuaran.Core.Idl.Codegen`, DECISIONS.md D280) — class **breaking**: no public signature moves, and a vocabulary that
  loaded is refused. `Declare.errors` names each such type, `enum '<name>' declares no case, so it has no value` (or
  `union '<name>'`), at `$.enums[i].cases` or `$.unions[i].cases`, beside the other declaration faults and in the
  order they are walked, so the artifact reader and `Proposal.applyDelta` refuse it there; it used to load, emit and
  round-trip, and was refused only where something first sampled it. The contract refusal `emptyEnumeration` is
  unchanged, and a vocabulary that earns it now earns the declaration fault as well. **What breaks, and what a
  consumer does:** a vocabulary declaring a type with no case gives it a case or removes it. **Generated F# moves
  only where a member carries a support doc block and an authored annotation:** under a block that opens with `<`
  the annotation's lines are an explicit `<remarks>`, encoded, where they were text the compiler could not parse
  (FS3390) and a tool reading the comment dropped; under a text block an annotation whose doc opens with `<` is
  printed as authored, with no `<summary>` of its own. A member with only one of the two emits the bytes it did.
- **A model's argument object is read by Core, and an emitted op is read through the codec its surface carries**
  (Phase 714, `Fuaran.Core.Function`, `Fuaran.Core.AiSurface`, `Fuaran.Core.Conformance`, DECISIONS.md D282) — class
  **breaking**: `union-widening` on `Families.Takes`, which gains `EmissionSurfaceWitness`, and a changed answer of
  `Function.toJsonSchema`; every other move is additive. `CapabilityCodec.decodeArgs` / `decodeArgsJson` read the object
  `toJsonSchema` describes into the argument list every seam operation takes, in declaration order and each value in
  its space's canonical spelling: an integer hole reads a JSON integer or a number with no fractional part, a number
  hole either, a slot an object, a document any value. They answer every `DecodeError` at once (`UndeclaredMember`,
  `WrongKind`, `OutOfRange`, `MissingField`; a member given twice is `OutOfRange` at its second occurrence), and an
  `Ok` is a list `Capability.validateArgs` admits. The schema and the reader come from one entry per value space.
  `EmissionSurfaceWitness` (`Surface`, `Emission: Codec<'Op>`) embeds the frozen `AiSurfaceWitness` and is frozen at
  birth; `AiSurface.decodeEmission` / `decodeEmissionJson` read one emitted op with the codec's strict reader, and
  `AiSurface.kindSchemas` lists a `kind`-keyed union codec's case schemas for the catalogue. `capabilityLaws` gains a
  law (twelve where it reported eleven): over drawn signatures and argument objects, `toJsonSchema` admits an object
  exactly when `decodeArgs` reads it. `Conformance.emissionLawsAt` is a new family. `capabilityArgumentLaws`
  (`conformance/laws/capability-argument-laws.json`, twenty vectors) is a new vector family of this repository's; it is
  not a copy in the shared corpus. **What breaks, and what a consumer changes:** `toJsonSchema` now states
  `"additionalProperties": false`, and a slot's property requires `kind` (a string, or `{"enum": [k]}` for a slot
  constrained to `k`), so a consumer pinning its bytes re-pins them; an argument object the old schema admitted and the
  seam refused is now refused by the schema too. An exhaustive `match` over `Families.Takes` is incomplete until it
  adds an `EmissionSurfaceWitness` arm. `StringLen`'s bounds are still counted in UTF-16 code units, which JSON
  Schema's `minLength` / `maxLength` count in code points: the two differ on text outside the Basic Multilingual Plane
  (D282.5).
