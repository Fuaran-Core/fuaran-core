# Wire layer timing — 2026-10-05 — i7-9700 — Phase 368 (the value tree's share of a large-array decode, and `Json.Reader`)

Phase 368 asked how much of decoding a large homogeneous array goes on building the `JVal` tree, once
365 to 367 had removed the per-character costs. It said to add a typed reader only if that share is
material. This file records the threshold, which was written down before anything was timed. It also
records the measurement, the reader that shipped, and its figures, and shows that `parse` did not
slow. How to run and read the harness tables: [`docs/wire-performance.md`](../../docs/wire-performance.md).
Earlier baselines: [`364`](2026-10-04-i7-9700-phase-364.md), [`365`](2026-10-05-i7-9700-phase-365.md),
[`366`](2026-10-05-i7-9700-phase-366.md), [`367`](2026-10-05-i7-9700-phase-367.md). The decision record
is DECISIONS.md D121.

- **Machine:** Intel Core i7-9700 @ 3.00 GHz, 8 logical processors, Windows 10.0.26200, mains power.
- **.NET:** SDK 10.0.401, Release builds.
- **node:** v25.9.0. **Fable:** 5.0.0 (fable-library-js 5.0.0). The compiler ran from the toolchain of
  a checkout that owns one, writing to a scratch directory (DECISIONS.md D55).
- **Trees:** before, fuaran-core `main` at `9e63186` (365, 366 and 367 landed); after, the same plus
  this phase.
- **Probes.** The tree measurement and the in-process before/after comparisons are scratch programs, not
  committed. Each samples its cases interleaved, rotating the order every round, with 31 samples of
  batches of at least 50 ms. Each reports the median ms per call and an A/A control: the first case
  timed again as a third case. On .NET, bytes allocated per call come from
  `GC.GetAllocatedBytesForCurrentThread` over 20 calls.

## The threshold, stated before the measurement

- **A**: `Json.parse`, then the best-case typing pass a consumer makes today. That pass is one
  tail-recursive walk of the element list into a pre-sized array.
- **B**: the same text read by the parser's own string and number routines, unchanged, straight into
  a `string[]` / `float[]`. B builds no `JVal`, no element list and no typing pass. It is the upper bound
  of any reader, because it keeps every cost a reader must still pay.
- **tree share = (A − B) / A.**

MATERIAL meant all of these:

- (a) a tree share of at least 20 per cent on the `state` corpus (the named first consumer's shape), on
  at least one host, in both runs;
- (b) a difference beyond the A/A control;
- (c) B's typed output equal to A's, element for element, checked before timing.

The bar is 20 per cent, not Phase 367's 5, because a reader is new public surface. Its refusals must
equal `parse`'s on two hosts for good, inside the `JsonParse` proof cone. 365 to 367 each bought 16 to
20 per cent, and A − B is an upper bound that a real reader's API layer only shrinks.

clears the bar on both hosts in both runs, and on .NET it is several times the spread, so the reader
ships.**

## The refusals agree, on both hosts

The differential is `JsonReaderTests` in the suite. A scratch copy compiled by Fable runs the same
check under node. It runs eight readings: `value`, `strings`, `floats`, `ints`, `items` of values,
`members` of values, the state shape, and `items` of `strings`. The inputs are the 26 json vectors of
the codec refusal corpus, the five benchmark corpora, and 4,000 generated documents of eight shapes.
Each document is also padded, truncated, cut and spliced with a grammar character, for 28,031 inputs.
Each (reading, input) outcome is compared with `parseDetailed` plus the same typing. A typed value is
compared as rendered. A refusal is compared on its kind, message and position. A mismatch must occur
exactly where typing the tree fails.

- **.NET and node each:** 224,248 outcomes, 0 disagreements. The outcomes split 20,395 accepted, 23,677
  mismatched and 180,176 refused.
- **Across hosts:** the two outcome listings (one FNV-1a per outcome) are byte-identical, apart from
  line endings.
- **The comparison can fail.** In the suite, the outcomes with every refusal position moved by one
  disagree on every refusal. A reader built without the precedence rule, so that it reported a
  mismatch without first asking `parseDetailed`, disagreed on 17,919 inputs of the `strings` reading in
  the suite and on 109,521 outcomes under node. It was reverted.
