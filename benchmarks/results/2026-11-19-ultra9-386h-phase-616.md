# A parse copies no number or literal token — 2026-11-19 — Core Ultra 9 386H — Phase 616

Phase 616 asked whether `Json.parse` pays for a substring per number token, per `true`, `false` or `null`, and
per object member on the path that erases a member `null`, and, if it does, for the .NET path to read those tokens
in place. The review that filed it estimated the cost by reading the code; this file measures it. The before
figures were taken first, on the tree the phase was cut from, before any change.

- **Machine:** Intel Core Ultra 9 386H, 16 logical processors, Windows 10.0.26300. Other builds were running on
  the machine; the timed runs were taken under a shared benchmark lock that kept every other timed benchmark run
  off it, but builds were not excluded. The allocation column is the measure the phase is about, and it does not
  depend on load.
- **.NET:** runtime 10.0.8, SDK 10.0.203, Release build of `Fuaran.Core.Wire`.
- **Harness:** [`json-parse-phase-616.fsx`](json-parse-phase-616.fsx), beside this file, run as its header says,
  one case per process. It checks that every parse answers the value its text was rendered from before it times
  anything.
- **Cases:** `floats` and `state` are the wire benchmark's corpora of those names; `state` carries no number or
  literal token and is the control. `ints` is 10,000 integer tokens, `literals` 10,000 `true` / `false` tokens,
  and `members` 2,000 objects of five integer members read under `ReadOptions.tolerantOfNull`.
- **Columns:** Phase 607's: wall time per call in milliseconds (mean, median, p95), bytes the calling thread
  allocated per call, and generation-2 collections per call. `token bytes` is what one string per token costs
  (24 bytes of header and length, two per unit, rounded up to 8) summed over the tokens the parse meets, the
  member look-ahead's four-unit string included.
- **Threshold, written before the first run:** the change is material if the token strings are at least 10 % of
  the bytes a parse allocates on one of `floats`, `ints` or `literals`; below that on all three, the phase closes
  with this file and no code change.
- **Trees:** before, `95b1a2f1`; after, `054a35fd`.

## Reading it

- **The cost was real, and it was allocation, exactly the copies.** A parse of the float corpus allocates 972,922 to
  972,928 bytes where it allocated 1,497,312: 524,390 bytes less, the 524,392 bytes the token strings cost, to within the
  noise of the allocation counter. The literal corpus falls by 320,000 bytes, its token strings to the byte. The
  control, `state`, which holds no number or literal token, is unchanged (2,761,724 to 2,761,738 bytes
  in every run).
- **The integer cases fall by more than their token strings**, because the parser's integer read now answers a
  `ValueOption` where it answered an `option`: `ints` falls by 578,663 bytes, its 368,664 bytes of token strings and
  24 bytes for each of the 8,750 tokens that read as `JInt`; `members` by 879,848, its 639,848 bytes of token and
  look-ahead strings and 24 bytes for each of its 10,000 integer members.
- **The grammar check allocated nothing before either.** The float corpus's fall is its token strings and nothing
  more, so the `option` steps of the grammar function were not on the heap on this runtime; they answer a
  `ValueOption` now because the function was rewritten to take a range, not for a saving it shows here.
- **Time follows, within the noise.** Medians on the float corpus are 1.02 and 1.07 ms before and 1.06 and 1.05 ms
  after, on `ints` 0.55 and 0.58 before and 0.51 and 0.50 after, and on `literals` 0.22 and 0.29 before and 0.21 and
  0.21 after; generation-2 collections stay at about one in 250 parses. The timings were taken under a shared
  benchmark lock that excluded other timed runs but not other builds, so the allocation column is the evidence.
- **The falsifier held both ways.** Every case checks that its parse answers the value its text was rendered from
  before it is timed. The suite's new sweep reads every number-alphabet token of up to five characters, the
  literals and their near misses, alone and after a prefix, and requires the same answer, refusal sentence and
  position; with the int53 bound deliberately compared from the token's start instead of its first digit, the sweep's
  2^53 case failed, and restored it passes.
